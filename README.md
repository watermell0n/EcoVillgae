# 이코빌리지 MVP

- 기준일: 2026-07-30
- 상태: API·이벤트 계약, MVP 데이터 설계, Flyway DDL·DB 무결성 테스트 코드 완료
- 대상: 초등학교 4~6학년

이 문서는 MVP 범위만 설명합니다. 상세 결정은 [API 명세 전 결정사항](docs/API_PRE_DESIGN_DECISIONS.md), 공통 구현 계약은 [API 공통 규칙](docs/API_COMMON_RULES.md), 학년·규모별 조합은 [추천 코스](docs/COURSE_RECOMMENDATIONS.md), 구현 기술은 [기술 스택](docs/TECH_STACK.md)을 기준으로 합니다.

## 1. 제품 한 문장

교사가 학년과 추천 규모에 맞는 코스와 모듈을 선택하면, 학생이 학교 지급 태블릿으로 자율시간과 교사 지도 활동에서 지속적인 학급 경제를 경험하는 교육 플랫폼입니다.

## 2. 확정 범위

- MVP 대상은 초등학교 4~6학년입니다.
- 중학생 코스와 자리·부동산 모듈은 MVP에서 제외합니다.
- `1회·1주·1달·1학기`는 실제 날짜나 회차를 고정하지 않는 **추천 규모 라벨**입니다.
- 실제 운영기간과 활동 횟수는 교사가 자유롭게 정합니다.
- 학급 코드는 서버가 혼동하기 쉬운 문자를 제외한 영문 대문자·숫자 8자로 전역에서 유일하게 생성하며 개설 후 변경하지 않습니다.
- 학급 소유 교사는 개설 시 학급 화폐 단위명을 필수로 입력합니다. 한글·영문·숫자 1~10자와 금칙어를 검증하고 개설 후에는 변경하지 않습니다.
- 코스는 AI가 생성하지 않고 팀이 검증한 추천표를 사용합니다.
- `1회` 코스에는 퀴즈·게임을 기본 추천하지만, 교사는 실제 일정·예산·선행조건이 유효하면
  다른 모듈도 선택할 수 있습니다. 코스 라벨만으로 기능을 금지하지 않습니다.
- `1회` 코스도 개설 메타데이터로 단위명을 입력하며, 지갑·금액 화면은 교사가 선택하고
  활성화한 금액 관련 모듈이 있을 때만 사용합니다.
- 금융 모듈 기본 추천은 초4 `정기예금`, 초5 `정기예금·정기적금`, 초6 `정기예금·정기적금·가상 투자`입니다.
- 교육용 대출은 초5 1학기와 초6 1학기에 기본 추천합니다.
- 교사는 추천 모듈을 추가하거나 제외할 수 있으며 시스템은 선수 모듈과 영향을 안내합니다.

## 3. 사용자와 화면

| 사용자·화면 | 기술·역할 |
| --- | --- |
| 학생 앱 | React Native·Expo 기반 Galaxy Tab 앱에서 지갑, 상점, 캐릭터, 개인거래, 금융상품, 퀴즈·투표와 개인 리포트 사용 |
| 교사 웹 | Next.js에서 수업 진행, 자율시간 제어, 경제교실 개설, 정책·콘텐츠 관리, 거래 승인, AI 운영 지원과 리포트 제공 |
| 학교·플랫폼 관리자 웹 | Next.js에서 학교 범위 지원과 플랫폼 운영 기능 제공 |
| 교실 공용 화면 | Next.js 발표용 화면에서 문제, 타이머, 익명 집계와 공개 가능한 결과만 표시 |

- 학생은 학교에서 지급한 개인 태블릿을 사용합니다.
- 개인 잔액, 금융상품, 세금과 평가 결과는 다른 학생이나 공용 화면에 공개하지 않습니다.
- 교사의 수업 진행 화면과 관리 화면은 하나의 Next.js 웹 안에서 같은 인증 세션, API와 권한 정책을 사용합니다.
- 교사는 학교 계정 OIDC로 로그인하며 백엔드는 서명·발급자·대상·만료와 사전 등록 계정을 검증합니다. 외부 계정 비밀번호는 이코빌리지에 입력하거나 저장하지 않습니다.
- 경제교실에는 학급 소유 교사 1명과 공동 담당 교사 0명 이상을 둘 수 있습니다.
- 소유 교사는 학급 구조·경제정책·모듈·종료를, 공동 담당 교사는 수업·승인·일상 운영을 담당합니다.

최종 12개 조합은 [추천 코스](docs/COURSE_RECOMMENDATIONS.md)를 따릅니다.

## 5. MVP 모듈

API와 클라이언트가 사용하는 canonical code, 입력 별칭, 금액 사용 여부와 선수 조건은
[정식 선택 모듈 카탈로그](docs/MODULE_CATALOG.md)를 따릅니다. `WALLET`은 선택 모듈이 아니라
금액 기능이 처음 필요할 때 준비되는 기술 인프라입니다.

### 5.1 공통 기반

- 학급 코드·출석번호·닉네임·비밀번호 기반 로그인
- 교사용 학교 계정 OIDC 로그인과 앱·웹 다중 세션
- 서버 생성 전역 유일 학급 코드와 개설 후 변경할 수 없는 학급 화폐 단위명
- 로그인 실패 횟수로 학생 계정을 잠그지 않으며, 비밀번호 재설정은 기존 이코빌리지 본인 확인 절차를 재사용
- 경제교실과 역할·권한
- 지갑과 수정하지 않는 거래 원장
- 정책 스냅샷과 감사 기록
- 알림과 기본 리포트
- 자율시간·교사 지도 활동·잠금 상태 제어

### 5.2 경제활동

- 역할별 급여와 월급명세서
- 소득세·부가세·개인거래세
- 기본 세금 사용처와 교사가 수정할 수 있는 공동기금 사용처
- 공식 디지털 상점과 실제 상품 상점
- 배포 지역에서 퍼블릭 도메인이 확인된 원작 기반 캐릭터와 꾸미기용 디지털 아이템
- 학생 간 상대 지정 개인거래와 교사 승인
- 정기예금과 정기적금
- 규칙 기반 가상 투자와 실제 가격 이력 선 그래프
- 교육용 대출, 분할상환, 연체와 기본 신용·성실도
- 공동기금, 공공예산과 익명 투표

### 5.3 퀴즈

- 콘텐츠 유형은 `ECONOMY·NONSENSE`, 실행 모드는 `GAME·TEST`로 분리합니다.
- 문제은행·생성·수정·AI 초안 승인 권한은 교사에게만 있습니다.
- 게임형은 정답·속도 점수와 교사가 선택한 경우 1~3위의 닉네임·장착 캐릭터 공개를 지원합니다.
- 평가형은 학생별 응시·비공개 결과를 사용하며 속도 보너스·순위·화폐 보상을 제공하지 않습니다.
- 코스 라벨만으로 GAME 화폐 보상을 금지하지 않습니다. 교사가 금액 관련 모듈과 보상을
  활성화한 경우에만 실제 발행액·예산·보상 비중 규칙을 통과해 지급하며 TEST에는 지급하지 않습니다.
- 1주 이상 게임형 넌센스 퀴즈는 동일한 소액 참여 보상만 제공하며 경제 퀴즈 상한의 30% 이하로 제한합니다.
- AI 문제 생성은 교사가 입력한 주제와 학습목표를 이용한 객관식·OX 초안으로 제한합니다.
- 애매하거나 잘못된 문항은 `INVALIDATED` 처리 후 재채점하고 보상 오류는 복구 거래로 정정합니다.

## 6. MVP 우선 AI

### 6.1 AI 경제 밸런싱

- 화폐량, 소비율, 판매 속도, 재고, 자산 집중도와 금융상품 참여를 집계합니다.
- 가격·재고·활동 보상·세율·물가 조정률·예금금리·대출금리의 안전한 범위를 제안합니다.
- 시스템이 지표와 허용 범위를 계산하고 AI는 원인·대안·예상 효과를 설명합니다.
- 학생 5명 미만 또는 관련 거래 10건 미만이면 `데이터 부족`으로 처리합니다.
- 교사 승인 후 시스템이 적용하며 과거 거래와 기존 금융상품 조건은 소급 변경하지 않습니다.

### 6.2 교사용 AI 챗봇

- 학급 설정, 경제 지표, 상점과 금융상품의 학급 집계, 퀴즈 집계와 정책 변경 이력을 조회합니다.
- MVP에서는 학생 개인 분석을 제공하지 않습니다.
- 답변에 근거 지표, 조회 기간, 데이터 갱신 시각, 대응안과 부작용을 표시합니다.
- 교사당 하루 30회, 응답 제한 20초, 자동 재시도 1회를 기본값으로 둡니다.
- 질문·답변 원문은 생성 후 30일, 모델·프롬프트·비용·성공·실패 메타데이터는 AI 실행 후 1년 보관합니다.

### 6.3 AI 경제 이벤트

최초 템플릿은 물가, 공급, 세금, 금리, 가상 투자 뉴스, 활동 보상과 공동기금 7종입니다.

- AI는 이야기·선택지·진행 문구를 만들고 규칙 엔진이 수치와 효과를 결정합니다.
- 초4는 물가·공급·공동기금, 초5는 세금·예금·적금 금리까지, 초6은 전체 이벤트를 사용할 수 있습니다.
- 1회 코스에는 AI 경제 이벤트를 기본 추천하지 않지만, 교사가 관련 모듈을 선택하고 학년·
  실제 일정·정책이 유효하면 사용할 수 있습니다.
- 교사 승인 전에는 학생에게 공개하거나 효과를 적용하지 않습니다.
- AI가 학생 계좌, 데이터베이스와 투자 가격을 직접 변경하지 않습니다.

## 7. 핵심 정책

### 7.1 거래

- 모든 금액·아이템 변경은 서버 거래 원장을 통과합니다.
- 완료 거래는 수정·삭제하지 않고 오류는 원거래에 연결된 복구 거래로 정정합니다.
- 정책 변경은 이후 거래부터 적용하고 거래에는 당시 정책 스냅샷을 남깁니다.
- 잔액·재고 부족과 중복 요청은 일부만 처리하지 않고 전체 실패합니다.
- 정상 완료 상품 구매와 개인거래에는 학생 환불 기능을 제공하지 않습니다.

### 7.2 학생 앱 운영 상태

```text
CLOSED | AUTONOMOUS | GUIDED
```

- 우선순위는 `GUIDED > 교사 수동 설정 > 반복 일정`입니다.
- 교사가 지도 활동을 시작하면 참여 학생 앱은 활동 전용 화면으로 전환되고 공용 화면에는 공개 가능한 정보만 표시합니다.
- 자율시간 종료 후 새 구매·거래·금융 신청·투자 주문을 차단합니다.
- 종료 전에 서버가 접수한 거래는 원자적으로 완료합니다.
- 진행 중 지도 활동은 자율시간 종료와 관계없이 계속합니다.
- GPS와 위치 추적은 사용하지 않고 학교 지급 태블릿과 교사 개방 상태로 통제합니다.

### 7.3 경제교실 종료

```text
ACTIVE → CLOSING → READ_ONLY → ARCHIVED
```

- 교사가 종료를 시작하고 미완료 거래·주문·금융상품·활동을 점검합니다.
- 예금·적금은 교실 종료 불이익 없이 정산하고 투자는 최종 가격으로 매도합니다.
- 대출은 지갑에서 가능한 금액을 상환하고 부족액은 음수 잔액 없이 `종료 시 미상환`으로 기록합니다.
- 최종 잔액·금융상품·학습 결과 스냅샷 생성 후 변경을 금지합니다.

### 7.4 보관·이월

- 학생은 `READ_ONLY` 전환 후 30일, 교사·학교 관리자는 `READ_ONLY` 전환 후 1년 동안 허용 데이터를 조회할 수 있습니다.
- 새 학급에 잔액·아이템·금융상품·개인거래·학습기록을 자동 이월하지 않습니다.
- 코스 템플릿, 모듈 설정과 승인된 퀴즈만 복사할 수 있습니다.
- 거래·금융·정책·감사·퀴즈 기록은 `READ_ONLY` 전환 후 1년 보관합니다.
- 보관기간 종료 후 학생 식별 연결정보를 삭제하고 필요한 경우 재식별 불가능한 집계값만 남깁니다.
- 삭제된 식별 연결정보는 백업에 최대 30일 더 잔존할 수 있으며 백업 만료 후 제거합니다.

## 8. 기술 기준

- 학생 앱: React Native + Expo + TypeScript
- 교사·관리자 웹과 교실 공용 화면: Next.js App Router
- 핵심 API: Java 21 + Spring Boot 4.1
- AI 모듈: Python + FastAPI + Pydantic
- 기본 AI: AWS Bedrock + OpenAI 어댑터
- 클라우드: AWS 서울 리전, ECS Fargate, RDS, ElastiCache, S3, CloudFront, SQS
- CI/CD·인프라: Jenkins, EAS, Terraform

세부 내용은 [기술 스택](docs/TECH_STACK.md)과 [학생 앱·교사 웹 전환 계획](docs/CLIENT_ARCHITECTURE_TRANSITION.md)을 따릅니다.

## 9. MVP 제외

## 10. 저장소 구조

```text
student-app/          React Native·Expo 태블릿 앱(앱 본체는 student-app/expo/)
teacher-web/          Next.js 교사 관리 웹·교실 공용 화면
backend/              Spring Boot 핵심 API·Flyway·DB 테스트
ai-service/           FastAPI AI 서비스
contracts/            OpenAPI·AsyncAPI 기계 판독 계약
assets/characters/    캐릭터 원본·최적화 에셋
infra/                Jenkins·Terraform
docs/                 제품·API·데이터·UX·AI·디자인 문서
scripts/              문서·계약·스키마 정적 검사
```

로컬 PostgreSQL 17, Redis와 OpenTelemetry Collector는 `.env.example`을
`.env`로 복사한 뒤 다음과 같이 실행합니다.

```bash
docker compose up -d --wait postgres redis
```

기본 `docker compose up -d`도 PostgreSQL·Redis만 실행합니다. 백엔드와 AI·관측 서비스까지 컨테이너로 함께 실행할 때는 `app` 프로필을 사용합니다.

```bash
docker compose --profile app up -d --build
```

학교 태블릿에서 앱을 실행할 때는 `EXPO_PUBLIC_API_BASE_URL`의 `localhost`를
개발 PC의 같은 네트워크 IP로 변경합니다.

팀의 작업 순서, 경로별 담당과 충돌 방지 규칙은
[팀 일정·협업 방식](docs/TEAM_SCHEDULE_AND_WORKFLOW.md)을 따릅니다.
로컬·Jenkins·Terraform 준비 범위와 AWS 구축 시점은
[인프라 기준선](docs/INFRASTRUCTURE_BASELINE.md)을 따릅니다.
