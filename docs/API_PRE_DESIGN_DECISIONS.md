## 2. 코스·난이도

- 추천표는 AI 결과가 아니라 버전 관리되는 제품 데이터입니다.
- 모든 1회 코스는 퀴즈·게임만 사용하고 지갑·소득·상점·금융상품·화폐 보상을 사용하지 않습니다.
- 1주 이상 금액 모듈에는 지갑·거래원장이 필수입니다.
- 난이도는 초4 입문, 초5 기본, 초6 심화를 기본으로 합니다.
- 교사는 추천을 수정할 수 있고 선수 모듈과 제외 영향을 확인합니다.
- 학급 코드는 서버가 `ABCDEFGHJKMNPQRSTUVWXYZ23456789` 문자 집합에서 8자를 안전하게 임의 생성하고 전역 유일 제약 충돌 시 최대 5회 다시 생성합니다.
- 학급 화폐 단위명은 OWN이 개설 시 필수 입력하며 NFKC 정규화·앞뒤 공백 제거 후 한글 완성형·영문·숫자 1~10자만 허용합니다.
- 공백·문장부호·이모지·제어문자와 서비스 금칙어를 거절하며, 개설된 경제교실에서는 학급 코드와 화폐 단위명을 변경하지 않습니다.
- `1회` 코스도 개설 메타데이터로 단위명을 입력하지만 지갑·화폐 발행·금액 화면에는 사용하지 않습니다.

상세 조합은 [추천 코스](COURSE_RECOMMENDATIONS.md)를 따릅니다.

## 3. 퀴즈

### 3.1 실행

- `GAME`: 교사가 실시간 진행하고 정답·응답속도를 점수에 반영합니다.
- `TEST`: 학생별 응시, 정답 중심 채점, 비공개 결과를 사용합니다.
- 평가형은 순위·속도 보너스·화폐 보상을 사용하지 않습니다.
- 1회 코스는 두 모드 모두 화폐 보상이 없습니다.

### 3.2 문제 상태

```text
DRAFT → REVIEW_REQUIRED → APPROVED → PUBLISHED → RETIRED
```

- AI 문제는 `REVIEW_REQUIRED`에서 시작합니다.
- 게시 문제 수정은 새 버전을 만들고 퀴즈 실행에는 문제 스냅샷을 남깁니다.
- 학생은 종료 후 오류를 신고할 수 있습니다.
- 애매한 문항은 `INVALIDATED` 처리 후 점수·정답률·평가 분모에서 제외합니다.
- 결과·보상은 교사 확정 후 공개·지급하고 지급 후 오류는 복구 거래로 정정합니다.

### 3.3 넌센스

- 혼합 퀴즈와 전체 세션에서 30%를 넘으면 경고합니다.
- 교사는 사유를 기록하고 경고를 넘을 수 있습니다.
- AI 생성은 교사가 명시적으로 요청한 객관식·OX 초안만 허용합니다.
- 차별·혐오·성적·폭력적 표현, 학생 조롱, 과도한 유행어와 복수 해석 가능성을 검사합니다.

## 4. 거래·상점·개인거래

- 모든 금액·아이템 변경은 서버 거래 원장을 통과합니다.
- 완료 거래는 불변이며 오류는 원거래를 참조하는 복구 거래로 정정합니다.
- 정책은 이후 거래부터 적용하고 각 거래에 정책 스냅샷을 남깁니다.
- 세금·공동기금 사용처에는 제품 기본값을 제공하고 교사가 학급에 맞게 이름·설명·예산 항목을 수정할 수 있습니다.
- 개인거래는 `제안 → 상대 동의 → 교사 승인 → 금액·세금·아이템 동시 이전`입니다.
- 판매 등록 아이템은 중복 사용·판매를 막기 위해 잠그고 거래 취소·모듈 중지 시 해제합니다.
- 정상 완료 상품 구매와 개인거래에는 학생 환불을 제공하지 않습니다.
- 실제 상품의 운영 종료 취소는 학생 환불이 아니라 교사 정산·복구 절차입니다.
- 캐릭터 원작은 배포 지역에서 퍼블릭 도메인이 확인된 경우에만 사용하고 출처·저작권 상태·검토일을 기록합니다.
- 원작의 저작권 만료와 별개인 상표권·2차 창작물 권리는 출시 전에 별도로 확인합니다.

## 5. 금융상품

### 5.1 공통

- 실제 금융상품과 실제 종목을 사용하지 않습니다.
- 상품 일정은 코스 규모나 경제 회차가 아닌 명시된 날짜·단계를 사용합니다.
- 금리 변경은 신규 계좌·대출부터 적용하고 기존 상품은 가입·실행 당시 정책을 유지합니다.
- 금융 거래는 지갑·상품 상태·거래 원장을 하나의 트랜잭션으로 처리합니다.

### 5.2 정기예금

- 원금, 교육용 기간 금리, 가입·만기·중도해지 조건을 상품 스냅샷으로 저장합니다.
- 만기·중도해지 지급은 거래 원장을 통과합니다.
- 교실 종료 강제 정산에는 중도해지 불이익을 적용하지 않습니다.

### 5.3 정기적금

```text
계좌: ACTIVE → MATURED | EARLY_TERMINATED
납입: SCHEDULED → PAID | MISSED
```

- 납입 횟수 2~12회, 기본 4회, 유예기간 기본 3일입니다.
- 가입 시 자동납입에 동의하고 예정일에 서버가 자동 출금합니다.
- 잔액 부족 시 부분 출금하지 않고 `MISSED` 처리합니다.
- 유예기간에는 수동 재납입, 이후에는 해당 회차 추가 납입을 금지합니다.
- 미납은 대출 신용에 영향을 주지 않습니다.
- 회차별 이자는 `납입액 × 기간 금리 × 남은 회차 ÷ 전체 회차`입니다.

### 5.4 가상 투자

```text
DRAFT → OPEN ↔ PAUSED → CLOSED
```

- 실제 종목 대신 가상 자산 4종을 사용합니다.
- 학생 거래량은 가격을 바꾸지 않고 규칙 기반 시나리오·검증 이벤트만 가격을 변경합니다.
- 현재 가격 시장가 주문, 정수 단위만 지원합니다.
- 지정가·예약·공매도·신용거래·레버리지는 제외합니다.
- 총 투자 한도는 지갑의 50%, 한 자산은 총 투자 한도의 50%, 기본 최대 손실은 원금의 30%입니다.
- 학생 화면에는 과거 가격 선 그래프·현재가·등락률·최고가·최저가만 표시합니다.
- `CLOSED`에서 최종 가격으로 자동 매도하고 실현손익·수익률·선택 이유를 기록합니다.

### 5.5 교육용 대출

```text
APPLIED → APPROVED → ACTIVE → REPAID
        → REJECTED           → OVERDUE
```

- 교사 승인이 기본이며 학생당 동시 대출은 기본 1개입니다.
- 기간 단리를 사용하고 총상환액을 2~12회로 분할합니다.
- 예정일에 자동상환하고 잔액 부족 시 부분 출금·음수 잔액 없이 `OVERDUE` 처리합니다.
- 연체이자·연체료는 없고 유예기간 기본값은 3일입니다.
- 전액 중도상환은 수수료 없이 허용합니다.
- 신용은 `NORMAL·GOOD·CAUTION·RESTRICTED`로 관리하고 본인과 교사만 확인합니다.
- `GOOD`은 최대 -1%p, `CAUTION`은 최대 +1%p, `RESTRICTED`는 신규 대출을 차단합니다.

## 6. AI

### 6.1 책임

- Spring 핵심 API와 규칙 엔진이 지표·금액·허용 범위·거래 결과를 계산합니다.
- AI는 설명·요약·이벤트 문구·퀴즈 초안을 만듭니다.
- 교사가 공개·적용·수정·거절을 결정합니다.
- AI는 데이터베이스와 학생 계좌를 직접 변경하지 않습니다.

### 6.2 밸런싱

- 경제교실 개설 마법사의 마지막 단계에서 역할급여·소득세율·신규 예금금리·신규 대출금리를 우선 추천합니다.
- 상품 등록·수정에서는 가격을, 퀴즈 등록·세션 설정에서는 GAME 보상을 추천합니다. TEST와 1회 코스에는 화폐 보상을 추천하지 않습니다.
- 추천 수치는 Spring 규칙 엔진이 계산하고 AI는 근거와 주의점을 설명하며 교사가 적용·수정·건너뛰기를 결정합니다.
- 첫 학생 앱 개방 또는 첫 화폐 변경 지도 활동 전에 현재 설정의 필수값·허용 범위·발행과 회수 균형을 점검합니다.
- 교사 요청과 자동 모니터링에서 운영 지표를 분석합니다. 1주 이상 코스의 기본 자동 분석 구간은 7일이며 동일 길이·비중첩 구간을 사용합니다.
- 학생 5명 미만 또는 관련 거래 10건 미만이면 `데이터 부족`입니다.
- 가격·재고·보상·세율·물가·예금금리·대출금리를 제안합니다.
- 세율은 이후 거래, 금리는 신규 상품부터 적용합니다.
- `NORMAL`은 요약만 저장하고 `OBSERVE·WARN`에서만 AI 설명·제안을 생성합니다. 같은 학급·지표·방향·심각도의 같은 구간 알림은 중복 생성하지 않습니다.
- 자동 모니터링 결과와 설정 추천은 자동 적용하지 않으며, 교사 확인·수정·적용 여부를 감사합니다.

### 6.3 이벤트

- 물가·공급·세금·금리·가상 투자 뉴스·보상·공동기금 템플릿을 사용합니다.
- AI는 문구를 만들고 효과는 규칙 엔진이 결정합니다.
- 특정 학생 손익, 강제 대출, 잔액 직접 차감과 음수 잔액을 금지합니다.
- 교사 직접 요청과 자동 모니터링 추천 두 경로를 허용합니다. 자동 모니터링은 근거와 템플릿만 추천하고 교사 선택 후 초안을 생성합니다.
- 투자 뉴스는 기업을 생성하지 않고 고정된 시나리오 버전·가상 자산·가격 단계에 연결해 시장 시작 전에 생성합니다.
- 교사가 승인한 뉴스만 해당 가격 단계에서 공개하고 미래 단계의 뉴스와 가격은 학생에게 노출하지 않습니다.

### 6.4 챗봇·운영

- 학급 집계만 조회하고 학생 개인 분석은 제외합니다.
- 질문·답변 원문은 생성 후 30일, 실행 메타데이터는 AI 실행 후 1년 보관합니다.
- 교사당 하루 30회, 20초 제한, 자동 재시도 1회를 기본값으로 둡니다.
- Bedrock 기본, 관리자 승인 시 OpenAI 어댑터를 사용합니다.
- 학급·학교 AI 전체 끄기와 AI 실행 ID를 제공합니다.

## 7. 앱 운영·종료·보관

### 7.1 교사 역할

- 경제교실에는 소유 교사 1명과 공동 담당 교사 0명 이상을 둡니다.
- 학급을 생성한 교사가 최초 소유 교사가 됩니다.
- 소유 교사는 담당 교사·학급 구조·코스·모듈·경제정책·종료를 관리합니다.
- 공동 담당 교사는 지도 활동, 거래·대출 승인, 상품 수령, 복구 거래와 리포트를 담당합니다.
- 공동 담당 교사는 다른 담당 교사, 학급 구조, 경제정책과 종료 상태를 변경할 수 없습니다.
- 학교 관리자와 플랫폼 운영자는 교사의 수업 권한을 자동으로 상속하지 않습니다.
- 교사용 앱과 관리 웹은 같은 역할·권한 규칙을 사용합니다.

### 7.2 로그인

- 학생은 학급 코드·출석번호·닉네임·비밀번호를 사용하고 실명을 입력하지 않습니다.
- 로그인 실패 횟수로 학생 계정을 잠그지 않습니다.
- 비밀번호 재설정은 기존 이코빌리지의 본인 확인 가능한 절차를 재사용합니다.
- 닉네임 재설정 기능은 제공하지 않습니다.

### 7.3 학생 앱 상태

```text
CLOSED | AUTONOMOUS | GUIDED
```

- 우선순위는 `GUIDED > 수동 설정 > 반복 일정`입니다.
- 수동 열기 기본시간은 30분, 종료 알림은 5분·1분 전입니다.
- 종료 후 신규 변경 요청을 차단하고 서버 접수 거래는 완료합니다.
- 지도 활동 시작 시 참여 학생 앱을 활동 전용 화면으로 전환하고 공용 화면에는 문제·타이머·익명 집계·공개 결과만 표시합니다.
- 학생 화면은 교사 관리 화면을 그대로 복제하지 않습니다.
- GPS·위치 추적은 사용하지 않습니다.

### 7.4 경제교실 종료

```text
ACTIVE → CLOSING → READ_ONLY → ARCHIVED
```

- 미완료 개인거래 취소·아이템 잠금 해제
- 실제 상품 수령 완료 또는 운영 종료 취소
- 예금·적금 불이익 없는 정산
- 투자 최종 가격 자동 매도
- 대출 가능한 금액 우선상환과 부족액 `종료 시 미상환`
- 진행 활동 종료·취소와 AI 이벤트 이후 효과 중단
- 최종 잔액·금융·학습 스냅샷 생성

### 7.5 보관·이월

- `READ_ONLY` 전환 후 학생 조회 30일, 교사·관리자 조회·내보내기 1년
- 새 학급으로 학생 자산·금융·거래·학습데이터 자동 이월 없음
- 코스·모듈 설정과 승인 퀴즈만 복사
- 거래·금융·정책·감사·퀴즈 기록은 `READ_ONLY` 전환 후 1년
- 푸시 토큰·기기 연결은 `READ_ONLY` 전환 후 30일
- 보관기간 종료로 삭제한 식별 연결정보의 백업 잔존기간은 삭제 후 최대 30일

## 9. 구현 상태와 후속 순서

화면과 행동 경계는 [화면 ID·행동 명세](SCREEN_SPEC.md)를 따릅니다.
인증·응답·오류·멱등성·동시성·시간·금액 계약은 [API 공통 규칙](API_COMMON_RULES.md)을 따릅니다.

화면 행동별 HTTP API는 [HTTP API 명세](HTTP_API_SPEC.md), 실시간 채널·이벤트는 [WebSocket 명세](WEBSOCKET_SPEC.md)에서 확정했습니다.

PostgreSQL 물리 스키마, Flyway `V1_1`~`V1_11`, DBT-001~019와 MVP API 필드 매핑은 구현했습니다.

1. OpenAPI·AsyncAPI와 저장·projection 필드 매핑
2. 계약 기반 클라이언트·서버 인터페이스 생성
3. 서비스·E2E 인수 테스트와 개발 백로그 연결

논리 ERD와 PostgreSQL 물리 스키마는 역할·권한·화면·API 경계를 기준으로 완료했습니다.

상태 전이 상세 기준은 [핵심 상태 머신](STATE_MACHINES.md)을 따릅니다.

역할별 권한과 리소스 범위는 [역할·권한 매트릭스](PERMISSION_MATRIX.md)를 따릅니다.
