# 경제교실 지속형 MVP 일관성 점검

- 기준 명세: `docs/ECONOMY_CLASSROOM_MVP_SPEC.md`
- 점검일: 2026-07-28
- 점검 범위: 대화에서 확정한 제품 정책, 화면 책임, 상태, 거래 규칙, 기존 2일 체험형 구현과 목표 명세의 구조 차이

## 1. 점검 결론

제품 내부에서 동시에 성립할 수 없는 주요 결정은 아래 기준으로 해소했다.

- 선형 2일 체험 코스와 지속형 모듈 이용은 별도 개념으로 분리한다.
- `경제교실 생명주기`, `현재 이용 모드`, `지도 활동 상태`, `긴급 잠금`을 각각 분리한다.
- 교사의 화면을 학생에게 복제하지 않고 하나의 활동 상태를 역할별 화면에 동기화한다.
- 세금, 공공기금, 공식 상점 매출, 개인거래와 예금을 서로 다른 돈의 이동으로 처리한다.
- 게임 퀴즈와 평가 테스트를 별도 세션·보상 정책으로 처리한다.
- 디지털 상품, 실제 상품, 아이템, 개인거래소 등록과 자리 이용권을 서로 다른 도메인으로 처리한다.

목표 제품 명세 안에서 API 설계를 막는 미해결 제품 정책은 없다. 다만 현재 저장소의 2일 체험형 구현은 목표 명세와 구조가 다르므로, 새 API를 기존 `DAY1_*`·`DAY2_*` 단계에 직접 덧붙이는 방식은 피해야 한다.

## 3. 화폐 흐름 일관성 점검

### 3.1 화폐 흐름 분류

| 활동 | 학생 현금 | 예금 | 공공기금 | 학급 전체 화폐 |
| --- | ---: | ---: | ---: | ---: |
| 최초 지원금·월급·퀴즈 보상 | 증가 | 변화 없음 | 변화 없음 | 증가 |
| 소득세·부가세 | 감소 | 변화 없음 | 증가 | 변화 없음 |
| 공식 상점 상품가격 | 감소 | 변화 없음 | 변화 없음 | 감소 |
| 개인거래 | 구매자 감소·판매자 증가 | 변화 없음 | 수수료만 증가 | 수수료가 없으면 변화 없음 |
| 예금 가입 | 감소 | 같은 금액 증가 | 변화 없음 | 변화 없음 |
| 예금 원금 반환 | 증가 | 같은 금액 감소 | 변화 없음 | 변화 없음 |
| 기본 예금 이자 | 증가 | 계좌 종료 | 변화 없음 | 증가 |
| 공공기금 현금성 지원 | 증가 | 필요 시 증가 | 같은 금액 감소 | 변화 없음 |
| 공공기금 비현금 효과 | 변화 없음 | 변화 없음 | 감소 | 감소 또는 서비스 효과로 소비 |

세금은 화폐 소각이 아니라 학생 영역에서 공공기금 영역으로 이동한다. 교사 대시보드는 `학생 유통 화폐`, `공공기금`, `전체 화폐`를 구분해야 한다.

### 3.2 공식 상점

- MVP 공식 상점은 학생 운영 사업자가 아니므로 상품가격은 학급 경제에서 회수한다.
- 부가세만 학급 공공기금에 적립한다.
- 환불은 상품가격과 부가세를 각각 원래 위치로 되돌린다.
- 향후 학생 운영 상점은 매출 계정, 원가와 재고를 별도 모듈로 설계한다.

### 3.3 공공기금 집행

- 학생 지갑에 현금을 주는 사용처는 공공기금에서 같은 금액을 이전한다.
- 예금 이자 지원은 공공기금이 부담하는 추가 이자로 처리한다.
- 상점 할인 지원은 공공기금 부담액과 공식 상점 회수액을 함께 기록한다.
- 공공기금 잔액과 별개로 추가 화폐를 발행하지 않는다.
- 기본 정기예금 이자만 상품 정책에 따른 신규 화폐 발행으로 본다.

## 4. 상태 모델 점검

### 4.1 분리해야 하는 상태

| 대상 | 상태 |
| --- | --- |
| 경제교실 | `DRAFT`, `ACTIVE`, `ENDED`, `ARCHIVED` |
| 현재 이용 모드 | `CLOSED`, `AUTONOMOUS`, `GUIDED` |
| 긴급 잠금 | `true`, `false` |
| 지도 활동 | 준비, 호출, 대기, 진행, 마감, 결과, 종료 |
| 상품 | 예정, 판매 중, 품절, 종료 |
| 실제 주문 | 수령 대기, 수령 완료, 취소, 환불 |
| 거래소 등록 | 판매 중, 판매 완료, 취소, 만료 |
| 예금상품 | 준비, 가입 가능, 가입 마감, 종료 |
| 학생 예금계좌 | 활성, 중도해지, 만기 |
| AI 문제 | 생성 중, 검토 필요, 승인, 보관 |
| 투표 | 준비, 진행, 마감, 무효·결정, 집행 |

경제교실의 `GUIDED` 모드와 게임 퀴즈의 `진행` 상태를 같은 값으로 저장하면 안 된다. 하나는 학급 접근 모드고 다른 하나는 개별 활동의 상태다.

### 4.2 자율 이용 종료

- 종료 이후 신규 금액 변경을 거절한다.
- 종료 직전에 서버가 받은 원자 거래는 완료 또는 롤백한다.
- 거래소 판매 등록은 유지한다.
- 개별 테스트는 1분 유예 후 자동 제출한다.
- 지도 활동 종료 시 원래 자율 이용의 종료시각을 다시 계산한다.

## 6. 현재 구현과 목표 명세의 구조 차이

현재 코드에는 1일차·2일차의 고정 순서를 표현하는 `DAY1_*`, `DAY2_*` 단계와 단계 간 이동 조건이 존재한다. 예:

- `frontend/src/features/room/model/stages.ts`
- `backend/src/main/java/com/b201/bibim/domain/room/RoomStage.java`
- `frontend/src/pages/student/stages/*`

목표 제품은 장기 운영 중 모듈을 개방하고 지도 활동을 독립 실행하므로 다음 차이가 있다.

| 현재 2일 데모 구조 | 목표 지속형 구조 | 전환 원칙 |
| --- | --- | --- |
| 방마다 한 개의 현재 `DAY1_*`·`DAY2_*` 단계 | 경제교실 생명주기 + 이용 모드 + 독립 활동 세션 | 기존 단계를 새 전역 상태로 확장하지 않음 |
| 교사가 정해진 다음 단계로 이동 | 교사가 퀴즈·테스트·투표를 독립 선택 | 활동별 세션 도메인 생성 |
| 예금·투자 결과를 특정 2일차 단계에서 일괄 정산 | 경제 운영일에 계좌별 자동 만기 | 금융상품과 운영일 분리 |
| 2일 고정 퀴즈 | 문제은행 기반 게임·테스트 | 퀴즈 유형과 응시 세션 분리 |
| 퀴즈 보상에 소득세 정산 | 게임 보상은 즉시 비과세, 월급 회차 보상만 과세 | 기존 체험 템플릿은 레거시 정책 스냅샷 유지 |
| 고정 공동기금 선택지 | 템플릿·커스텀 예산안 | 예산안 버전과 집행 기록 추가 |
| 고정 자유활동 단계 | 반복 일정·임시 자율 이용 | 이용 권한 창구를 별도 도메인으로 추가 |
| 기존 상점 상품 구매 | 디지털·실제 상품, 인벤토리, 거래소 | 상품과 소유 아이템 분리 |

### 6.1 구현 전환 권고

1. 기존 2일 체험 코스는 `체험 템플릿` 또는 레거시 플로우로 유지한다.
2. 새 지속형 경제교실을 기존 `RoomStage` 열거형에 모두 추가하지 않는다.
3. 경제교실, 운영창, 지도 활동 세션, 모듈 설정과 경제 운영일을 별도 모델로 만든다.
4. 기존 거래·예금·투표 기능 중 재사용 가능한 계산 규칙과 테스트를 식별한다.
5. 기존 데이터 마이그레이션은 새 모델이 확정된 뒤 별도 설계한다.

## 8. 외부 검토가 필요한 비제품 항목

아래 항목은 제품 기능의 모순이 아니라 학교·운영·법무 환경에 따라 최종 운영값이 달라지는 항목이다.

- 학생 개인정보 보관기간과 파기 시점
- 학교 계정 체계 또는 교사 SSO 도입
- 실제 상품 중 음식의 학교별 운영 규정
- AI 공급자, 모델과 비용 한도
- 접근성 공식 인증 범위

MVP API는 이 항목을 하드코딩하지 않고 설정·교체 가능하게 설계한다.
