# 이코빌리지 MVP 이후 추가 모듈 및 발전 방향

- 기준일: 2026-07-28
- 상태: 후보 범위
- 주의: 이 문서의 기능은 현재 MVP 확정 범위가 아니며 일정과 구현을 약속하지 않습니다.

## 1. 문서 목적

MVP README에는 지금 만들 기능만 남기고, 이후 검토할 모듈과 확장 방향은 이 문서에서 분리해 관리합니다. 추가 기능은 MVP의 사용성, 경제 안정성, 교사 운영 부담과 학습효과를 검증한 뒤 우선순위를 다시 정합니다.

## 2. 대상 학년과 코스 확장

### 2.1 중학생 코스

MVP는 초등학교 4~6학년만 대상으로 합니다. 중학생 코스는 다음 개념이 필요한 시점에 별도 확장합니다.

- 중1: 예산관리, 비상금, 보험, 대출과 신용
- 중2: 상점 운영, 생산, 재고, 가격, 원가·매출·이익
- 중3: 투자, 위험관리, 주거, 청약과 자산 리포트

초등 코스의 문장만 어렵게 바꾸는 방식이 아니라 계산 난이도, 의사결정 책임, 거래 구조와 리포트를 함께 재설계해야 합니다.

### 2.2 코스 고도화

- 교사가 만든 코스 저장과 복제
- 학교·교사 간 검증된 코스 공유
- 학급 운영 결과를 반영한 추천 개선
- 지역과 학교 일정에 맞춘 학기 템플릿
- 특수교육과 읽기 수준을 고려한 접근성 코스

AI가 코스를 임의로 생성하는 기능은 충분한 검증 코스와 운영 데이터가 쌓인 뒤 별도로 판단합니다.

## 3. 추가 경제 모듈

### 3.1 금융생활

| 모듈 | 학습 목표 | 주요 선수개념 |
| --- | --- | --- |
| 적금 | 정기 납입, 목표 저축과 중도해지 이해 | 지갑, 예산, 예금 |
| 주식투자 | 위험과 수익, 정보 해석과 분산 이해 | 저축, 손실 가능성 |
| 보험 | 위험 이전, 보험료와 보장 이해 | 위험, 예산 |
| 대출·신용 | 원금, 이자, 상환, 연체와 책임 이해 | 지갑, 예산, 상환 |

실제 금융상품이나 실제 종목을 사용하지 않고 교실용 가상 상품과 결정론적 시뮬레이션을 사용합니다.

### 3.2 시장과 상점 운영

| 모듈 | 학습 목표 |
| --- | --- |
| 시장가격·물가 | 수요·공급, 가격 변화, 구매력과 인플레이션 |
| 생산·재고 | 생산량, 재고 부족과 보관 비용 |
| 원가·매출·이익 | 판매가격, 비용, 매출과 이익 구분 |
| 학생 운영 상점 | 역할 분담, 가격 결정, 판매와 결산 |

공식 상점과 학생 운영 상점의 돈 흐름과 권한은 분리해야 합니다.

### 3.3 자리·부동산

자리·부동산 모듈은 **MVP에서 제외**합니다.

향후 구현 시 교실 자리를 일반 상점 상품으로 판매하지 않고 `기간형 교실 공간 이용권`으로 다룹니다.

- 이용기간과 만료
- 교사가 정한 좌석 조건과 이용 규칙
- 학생 간 직접 재판매 제한
- 접근성·건강·수업 운영상 필요한 좌석 우선 배정
- 화폐가 부족한 학생도 기본 좌석을 보장하는 안전장치
- 자리 선택과 실제 부동산 소유 개념의 차이 안내

학습 재미보다 학생의 학습권과 교실 운영 안정성을 먼저 검증한 뒤 도입합니다.

### 3.4 공공경제와 생활경제

- 복지·사회안전망 고급 정책
- 세금 유형과 누진 구조의 기초
- 공공예산 편성과 결산
- 주거비와 임대의 기초
- 주거·청약
- 금융사기 예방과 디지털 결제

## 4. AI 발전 방향

### 4.1 투자 시나리오 생성기

- 가상 기업과 가상 뉴스를 생성합니다.
- 가격 경로와 수익률은 시드가 고정된 시뮬레이터가 결정합니다.
- 수익 순위보다 정보 해석, 위험 인식과 분산 근거를 평가합니다.
- 중학생 투자 모듈과 함께 검토합니다.

### 4.2 접근성·학년별 변환

- 같은 경제 개념을 읽기 수준에 맞는 문장과 숫자로 변환
- 쉬운 한국어와 단계별 계산 제공
- 핵심 용어, 정답과 금액의 일관성 자동 검사
- 원문과 변환문을 교사가 비교·승인

### 4.3 학생용 AI 학습 도우미

- 승인된 학습 자료 안에서만 답변
- 정답 대신 단계별 힌트 제공
- 다른 학생의 정보와 자산에 접근하지 않음
- 실제 금융 조언을 제공하지 않음

### 4.4 경제 역할극 NPC

- 상점 소비자, 은행 직원, 공공기금 담당자 등 제한된 역할
- 선택 버튼과 상태 머신 중심의 대화
- 거래 결과와 금액은 규칙 엔진이 확정

### 4.5 AI 교사 보고서

- 학급 단위 학습 목표와 반복 오개념 요약
- 근거가 연결된 다음 활동 제안
- 학생 개인 능력에 대한 자동 단정 금지
- 잔액과 투자 수익을 학습 성취로 사용하지 않음

### 4.6 장기 학습지도와 맞춤 추천

- 개념별 학습 상태 누적
- 부족한 선수개념과 다음 복습 활동 추천
- 데이터가 부족하면 추정하지 않고 `데이터 부족` 표시
- 공개 순위와 자동 반 편성에 사용하지 않음

## 5. 운영과 플랫폼 확장

- 공동 담당 교사와 학교 관리자 권한
- 여러 학급을 묶은 학교 단위 운영
- 학급 간 콘텐츠 공유와 승인
- 교사용 분석 대시보드 고도화
- 학교 정책에 맞춘 데이터 보관·내보내기·삭제
- 장애 시 수업을 계속할 수 있는 읽기 전용·복구 모드
- 태블릿 앱 패키징과 학교 단말 관리 연동

## 6. 도입 순서 원칙

1. MVP 거래 원장과 권한이 안정적으로 동작해야 합니다.
2. 초등 4~6학년의 1회·1주·1달·1학기 코스를 실제로 운영해 봅니다.
3. 학생 참여 기회, 자산 격차와 교사 운영 부담을 측정합니다.
4. 학습효과와 운영 필요가 확인된 모듈부터 작은 범위로 시험합니다.
5. 안전성, 개인정보와 교사 승인 구조를 검증한 뒤 정식 모듈로 전환합니다.

## 7. 모듈 승격 기준

후보 기능을 MVP 이후 정식 모듈로 승격하려면 다음 조건을 확인합니다.

- 해결하려는 교육·운영 문제가 명확한가
- 기존 모듈로 해결할 수 없는가
- 선수개념과 대상 학년이 정해졌는가
- 돈·아이템·학습 데이터의 소유와 이동이 명확한가
- 학생 간 격차와 낙인 위험을 통제할 수 있는가
- 교사가 이해하고 승인할 수 있는가
- 실패·취소·복구 정책이 정의됐는가
- 인수 테스트와 측정 가능한 성공 기준이 있는가
