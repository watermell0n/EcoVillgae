# 이코빌리지 API 명세 전 미확정 이슈

- 기준일: 2026-07-28
- 목적: 회의 후에도 해석이 갈릴 수 있는 부분을 API·ERD 작성 전에 확정

## 1. 이번 회의에서 확정되어 다시 논의하지 않을 항목

- MVP 대상은 초등학교 4~6학년이다.
- 중학생 코스는 MVP에서 제외한다.
- 코스 기간은 1회, 1주, 1달, 1학기다.
- 코스는 학년과 기간을 동시에 고려해 추천한다.
- AI가 코스를 생성하지 않고 팀이 검증한 추천표를 제공한다.
- 퀴즈 생성·관리는 교사에게만 보인다.
- 초기 퀴즈 콘텐츠는 경제 퀴즈와 넌센스 퀴즈다.
- AI 경제 밸런싱, 교사용 AI 챗봇, AI 경제 이벤트 생성을 MVP 우선 기능으로 둔다.
- 자리·부동산 모듈은 MVP에서 제외한다.

## 3. 코스 관련 세부 이슈

### 3.1 기간의 의미

달력 기간과 실제 수업 횟수는 학교 행사, 방학과 재량시간 운영에 따라 달라집니다. `1달=4주`, `1학기=16주`처럼 코드에 고정하면 예금 만기와 활동 일정이 어긋날 수 있습니다.

결정할 값:

- 기간별 권장 경제 운영 회차
- 회차를 교사가 수동으로 진행하는지 일정이 자동 진행하는지
- 결석·휴일로 회차를 건너뛸 때 처리
- 코스 기간 연장과 조기 종료 허용 여부

### 3.2 추천표의 표현

추천표에는 단순 체크 여부 외에 다음 정보가 필요합니다.

- 추천 이유
- 필요한 선수개념
- 반드시 필요한 기반 모듈
- 해당 학년에서 사용할 문장·숫자 난이도
- 기간 안에 완료할 수 있는 권장 활동 수
- 교사가 제외했을 때 사라지는 학습 흐름

추천표는 AI 모델의 결과가 아니라 버전 관리되는 제품 데이터로 저장하는 방안을 우선 검토합니다.

## 4. 퀴즈 관련 세부 이슈

### 4.1 퀴즈 분류 축

`경제 퀴즈·넌센스 퀴즈`는 콘텐츠 주제이고 `게임 퀴즈·평가 테스트`는 운영 방식입니다. 두 축을 하나의 퀴즈 유형으로 합치면 보상, 시간제한과 결과 공개 규칙이 복잡해집니다.

권장 모델:

- 콘텐츠 태그: `ECONOMY`, `NONSENSE`
- 실행 모드: `GAME`, `TEST`
- 생성·검토 권한: 교사
- 참여 권한: 교사가 공개하거나 시작한 학생

평가 테스트를 MVP에서 제외할 계획이라면 `TEST`를 지금 제거할지 데이터 모델만 남길지 결정해야 합니다.

### 4.2 넌센스 퀴즈 운영

- 경제교육 제품에서 넌센스 퀴즈가 담당할 목적
- 전체 퀴즈에서 허용할 비율
- 연령 부적합, 유행어와 차별 표현 검수
- AI가 넌센스 문제를 생성할 수 있는지
- 정답이 여러 개로 해석될 때 처리
- 경제 퀴즈와 다른 보상 정책을 적용할지

### 4.3 AI 문제 생성

- 교사가 업로드할 수 있는 자료 형식과 용량
- 시험지·교재의 저작권과 보관기간
- 출처가 부족한 문제를 생성하지 않는 기준
- 숫자형 정답 재계산과 복수정답 검사 방식
- 교사 수정·승인 전 학생 노출 차단
- 모델 장애 시 수동 문제 작성으로 전환하는 흐름

## 5. AI 운영 기능 관련 세부 이슈

### 5.1 경제 밸런싱 지표와 기준

다음 계산식과 임계치는 AI가 아니라 시스템 규칙으로 먼저 확정해야 합니다.

- 화폐 공급 증가율과 회수율
- 평균·중앙 잔액과 자산 집중도
- 소비율과 예금 참여율
- 상품별 판매 속도와 품절 위험
- 주요 상품을 구매할 수 있는 학생 비율
- 활동 보상 기회의 편차

학습 목표에 따라 높은 저축률이나 낮은 소비율이 정상일 수 있으므로 학년·코스·현재 회차를 함께 판단해야 합니다.

### 5.2 AI 경제 이벤트

확정이 필요한 내용:

- 최초 제공할 이벤트 목록
- 각 이벤트의 허용 학년과 코스
- 실행 가능한 경제 효과 명령
- 재사용 대기시간
- 모든 학생의 참여 기회 검사
- 적용 전후 자산 격차 허용 범위
- 취소·중단·복구 정책

AI는 이벤트 수치를 결정하지 않고 검증된 템플릿의 이야기와 선택지를 구성하는 역할로 제한하는 것이 안전합니다.

### 5.3 교사용 AI 챗봇

읽기·상담 중심이라는 원칙은 확정됐지만 다음 구현 결정을 남겨두고 있습니다.

- 조회할 수 있는 집계 데이터의 범위
- 대화와 추천 이력의 보관기간
- 답변에 표시할 근거 지표와 신뢰도 형식
- 모델 장애·시간 초과 시 보여줄 대체 화면
- 같은 질문에 다른 답이 나왔을 때 버전 추적 방식
- 사용량 한도, 응답시간과 비용 상한

### 5.4 AI 공통 기술 결정

- 사용할 모델과 공급자
- 국내 학교·아동 데이터 처리 조건
- 프롬프트와 모델 버전 관리
- 구조화 출력 스키마
- 금칙어, 유해 콘텐츠와 실제 금융조언 차단
- AI 결과 품질 평가 세트
- 교사 승인, 수정과 거절 이유 저장 방식
- AI 기능 전체를 끌 수 있는 학급·학교 설정

## 6. 제품·운영 관련 세부 이슈

### 6.1 학생 앱 배포와 기기 연결

현재 기술 스택은 Vue 기반이지만 사용자가 부르는 `학생 앱`의 최종 형태는 확정되지 않았습니다.

- 브라우저 웹, PWA 또는 앱 패키징
- 학교 태블릿 OS와 관리 정책
- 다른 태블릿에서 로그인할 때 교사 승인 필요 여부
- 브라우저 데이터 삭제 후 재연결 방식
- 네트워크 끊김 중 조회와 재접속 처리

### 6.2 자율시간 운영

- 교사 수동 개방과 반복 일정의 우선순위
- 종료 전 알림 시점
- 지도 활동이 시작될 때 자율활동 처리
- 자율시간 종료 시 작성 중 퀴즈 답안과 거래 제안 처리
- 학교 밖에서 조회까지 허용할지

### 6.3 한 학기 데이터

- 학기 종료 후 학생과 교사의 조회기간
- 새 학기로 잔액·아이템·학습기록을 이월할지
- 학급 삭제와 데이터 내보내기 권한
- AI 대화·추천 이력과 일반 거래 기록의 서로 다른 보관기간
