# AI 기능 단계별 개발 계획

- 기준일: 2026-07-30
- 상태: 실행 순서 확정
- 범위: 경제 설정 추천, 자동 모니터링·밸런싱, 교사용 챗봇, 경제 이벤트, 투자 뉴스, 교사용 퀴즈 초안

## 1. 진행 원칙

각 단계는 아래 순서로 진행합니다.

1. 시작 전에 이번 단계의 변경 파일·동작·제외 범위를 사용자에게 설명합니다.
2. Jira에서 기존 이슈를 찾고, 없으면 구현 가능한 크기로 생성해 진행 중으로 바꿉니다.
3. 계약·규칙·저장·화면 순서로 구현하고 단계 안에서 필요한 자동 테스트를 추가합니다.
4. 관련 문서와 기계 판독 계약의 정합성 검사를 실행합니다.
5. Jira 완료 조건을 갱신해 완료 처리하고 검증 결과와 추천 커밋명을 알립니다.

하나의 단계가 끝나기 전에는 다음 단계의 비즈니스 구현을 섞지 않습니다. 긴 단계는
계약, 백엔드, 화면, 통합 검증으로 나누되 각 작업은 독립적으로 검증·커밋할 수 있어야 합니다.

## 2. 현재 완료된 기반

- AI 제품 방향, 책임 경계, 지표·임계값, 안전·평가 기준
- Spring 외부 API와 FastAPI 내부 API v1.0 계약
- FastAPI 애플리케이션 공통 기반과 네 가지 생성 라우터
- Pydantic 구조화 모델, 표준 오류, 제한시간·재시도 경계
- 외부 모델 없이 재현 가능한 fake provider와 계약·장애 테스트
- 설정 추천, 자동 모니터링·알림, 이벤트 두 경로와 투자 뉴스 MVP의 제품 결정

아직 실제 Bedrock 호출, Spring 오케스트레이션, 규칙 엔진, 저장 마이그레이션과 교사
화면은 구현하지 않았습니다.

## 3. 권장 구현 순서

### 1단계. 계약 v1.1 동기화

목표: 새 흐름을 코드보다 먼저 기계 판독 계약으로 고정합니다.

- 외부 OpenAPI의 `API-AI-002·003·004·006`, 관련 읽기 API를 갱신합니다.
- 내부 OpenAPI에 `analysis_mode`, 설정 후보, 자동 모니터링 구간, 이벤트 출처와 투자 단계 연결을 추가합니다.
- Spring DTO와 Pydantic 모델의 허용 필드·enum·오류 코드를 같은 커밋에서 맞춥니다.
- `contracts/api-field-mapping.json`과 계약 정적 검증을 갱신합니다.

완료 기준:

- 문서, 외부 OpenAPI, 내부 OpenAPI, Spring DTO, Pydantic 모델에 같은 필드와 enum이 존재합니다.
- 추가 필드·누락 필드·잘못된 모드·잘못된 투자 단계 연결 계약 테스트가 통과합니다.
- 아직 정책 계산, DB 저장과 실제 모델 호출은 수행하지 않습니다.

추천 커밋: `feat: AI 운영 흐름 v1.1 계약 확장`

### 2단계. 경제 설정 추천·시작 전 점검

목표: 모델이 아닌 Spring 규칙 엔진이 안전한 후보값과 BLOCK·WARN을 계산합니다.

- 개설 설정의 급여·세율·예금금리·대출금리 추천기를 구현합니다.
- 상품 작성 문맥의 가격 추천과 퀴즈 GAME 세션의 보상 추천을 구현합니다.
- TEST·1회 코스 보상 금지, 정책 절대 범위, 예상 발행·회수 예산을 검사합니다.
- 첫 OPEN·첫 화폐 변경 지도 활동 전에 점검하고 입력 변경 시 결과를 만료시킵니다.
- 규칙 기반 결과와 교사 선택·수정·건너뛰기를 저장합니다.
- 선택적으로 FastAPI가 후보값의 근거·주의점만 설명하게 연결합니다.

완료 기준:

- 같은 입력은 같은 추천과 reason code를 반환합니다.
- AI가 꺼졌거나 공급자 장애가 발생해도 숫자 추천과 BLOCK·WARN이 동작합니다.
- BLOCK은 시작을 막고 WARN은 교사 확인 후 진행할 수 있습니다.
- AI 출력이 규칙 엔진의 값·범위를 바꿀 수 없습니다.

추천 커밋: `feat: 경제 설정 추천 및 시작 전 점검 구현`

### 3단계. 자동 모니터링·알림

목표: 운영 지표를 주기적으로 계산하고 필요한 경우에만 교사에게 설명·제안합니다.

- 1주 이상 코스의 7일 비중첩 분석 스케줄과 실행 멱등 키를 구현합니다.
- 기존 16개 지표, 데이터 충분성, NORMAL·OBSERVE·WARN 판정을 Spring에 구현합니다.
- NORMAL은 모델 미호출, OBSERVE·WARN만 FastAPI 생성으로 연결합니다.
- 제안 심각도·지표·방향·분석 구간과 중복 키, ACKNOWLEDGED 결정을 저장합니다.
- 악화·회복·다음 구간 재발 알림과 교사 대시보드 조회를 구현합니다.
- 어떤 결과도 교사 APPLY 없이 정책을 변경하지 못하게 합니다.

완료 기준:

- 중복 스케줄·메시지 재처리에도 같은 구간 실행과 알림이 하나만 남습니다.
- 최소 데이터 미충족·NORMAL에서는 모델을 호출하지 않습니다.
- COT는 확인만, OWN만 정책 적용이 가능합니다.

추천 커밋: `feat: AI 경제 자동 모니터링과 알림 구현`

### 4단계. 경제 이벤트 두 경로

목표: 교사 직접 요청과 모니터링 추천이 같은 안전·승인 절차를 사용하게 합니다.

- `TEACHER_REQUEST·MONITOR_RECOMMENDATION` 출처와 원본 제안 참조를 저장합니다.
- 자동 모니터링은 템플릿·근거만 추천하고 교사 선택 후 전체 초안을 생성합니다.
- 같은 구간·근거·템플릿의 중복 추천을 억제합니다.
- 7종 템플릿, 학년 제한, 숫자 효과 금지와 교사 승인·거절을 연결합니다.

완료 기준:

- 출처와 근거를 바꾼 요청, 중복 추천과 승인 우회를 차단합니다.
- 이벤트 효과는 규칙 엔진 값만 사용하고 AI는 문구만 생성합니다.
- 승인 전에는 학생·공용 화면과 정책에 영향이 없습니다.

추천 커밋: `feat: 경제 이벤트 요청 및 모니터링 추천 경로 구현`

### 5단계. 투자 뉴스 MVP

목표: 기업 생성 없이 고정된 가격 시나리오에 안전한 뉴스만 연결합니다.

- 가상 자산 4종과 시드 기반 가격 단계를 먼저 고정합니다.
- 각 뉴스에 시나리오 버전·자산·가격 단계 연결을 필수로 저장합니다.
- 시장 시작 전 단계별 뉴스를 생성하고 교사가 수정·승인하게 합니다.
- 가격 단계 공개 시 승인된 뉴스만 함께 공개합니다.
- 학생 조회와 WebSocket에서 미래 가격·미승인 뉴스가 노출되지 않게 projection을 분리합니다.

완료 기준:

- AI가 기업, 가격, 수익률과 매매 추천을 만들지 않습니다.
- 같은 시드의 가격 경로와 뉴스 연결이 재현됩니다.
- 단계 N에서는 N 이후의 가격·뉴스를 어떤 학생 API에서도 조회할 수 없습니다.

추천 커밋: `feat: 가상 투자 단계별 AI 뉴스 생성 구현`

### 6단계. 실제 모델 공급자·프롬프트

목표: fake provider로 검증한 흐름을 Bedrock에 연결하고 장애 경계를 유지합니다.

- Bedrock 어댑터와 관리자 허용 시의 대체 공급자 어댑터를 구현합니다.
- 기능별 시스템 프롬프트·출력 스키마·버전을 저장합니다.
- 20초 deadline, 전체 최대 1회 재시도, 429·일시 장애 분류를 연결합니다.
- 토큰·비용·지연시간·모델·프롬프트 버전과 안전 결과를 기록합니다.
- 설정 추천, 모니터링, 이벤트, 투자 뉴스와 기존 챗봇·퀴즈 회귀 세트를 실행합니다.

완료 기준:

- 공급자 장애에서도 규칙 기반 운영 경로와 수동 화면이 유지됩니다.
- 안전·평가 출시 게이트를 모두 통과한 모델·프롬프트 조합만 활성화됩니다.
- 자격증명·프롬프트·학생 데이터가 로그와 오류 응답에 노출되지 않습니다.

추천 커밋: `feat: Bedrock 기반 AI 생성 어댑터 연동`

### 7단계. 교사 웹 통합

목표: 교사가 추천 근거와 위험을 이해하고 명시적으로 결정할 수 있게 합니다.

- 개설 마법사의 기본 경제값 추천과 최종 점검 화면을 구현합니다.
- 상품 가격, 퀴즈 GAME 보상 추천값 채우기와 수정 비교를 구현합니다.
- 자동 모니터링 알림·근거·영향·ACKNOWLEDGE·OWN 적용 화면을 구현합니다.
- 이벤트 출처·근거 검토와 투자 뉴스 단계별 검토 화면을 구현합니다.
- 로딩·데이터 부족·AI 꺼짐·시간 초과·공급자 장애 대체 상태를 구현합니다.

완료 기준:

- 추천값과 현재값, 허용 범위, 근거, 부작용을 한 화면에서 비교할 수 있습니다.
- COT·OWN 권한 차이와 승인 전 비공개가 UI와 API 모두에서 일치합니다.
- 오류 상태에서도 교사가 수동 설정으로 계속 진행할 수 있습니다.

추천 커밋: `feat: 교사 AI 운영 지원 화면 연동`

### 8단계. 통합 검증·출시 게이트

목표: 계약부터 학생 공개 경계까지 전체 흐름을 출시 가능한 상태로 검증합니다.

- Spring·FastAPI·PostgreSQL·교사 웹 통합 E2E를 작성합니다.
- 권한, 멱등성, 정책 버전 충돌, 자동 모니터링 중복, 승인 우회를 검증합니다.
- 미래 투자 정보 비공개, 개인정보 최소화, 보존·삭제와 감사 조회를 검증합니다.
- OpenTelemetry·Sentry·CloudWatch 대시보드와 AI 비용·실패 알림을 연결합니다.
- 학급·학교 AI 끄기와 직전 승인 프롬프트·모델 롤백을 검증합니다.

완료 기준:

- 계약·단위·통합·E2E·평가 세트와 문서 정합성 검사가 모두 통과합니다.
- 안전과 평가 문서의 출시 게이트에 실패한 조합은 배포할 수 없습니다.
- 운영자가 실행 ID로 요청부터 교사 결정까지 추적할 수 있습니다.

추천 커밋: `test: AI 기능 통합 검증 및 출시 게이트 완성`
