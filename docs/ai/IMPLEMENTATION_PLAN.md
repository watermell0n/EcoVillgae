# AI 서비스 독립 MVP 단계별 개발 계획

- 기준일: 2026-07-30
- 상태: 독립 AI MVP 10단계 완료
- 구현 단위: `ai-service` 단독 실행과 검증
- 후속 범위: Spring·DB·스케줄러·교사 화면 통합

## 통합 단계 현황 (2026-08-04)

독립 AI MVP 완료 후, Spring·교사 웹·학생 Expo 앱을 연결하는 1~6단계 구현을 마쳤다.
실행 환경, 시작 전 점검, 교사용 챗봇, 퀴즈 초안, 자동 모니터링·밸런싱, 단기·장기 투자
시나리오 생성과 학생 매수까지가 대상이다. 검증 명령과 결과, 실제 공급자 평가의 분리,
투자 정산 등 후속 범위는 [AI 통합 검증 기록](INTEGRATION_VERIFICATION.md)을 기준으로 한다.

이 문서의 1~10단계는 `ai-service` 독립 MVP의 완료 기록으로 유지한다. 아래에 적힌
“후속 통합 작업” 중 이미 연결된 항목은 위 통합 검증 기록을 우선하며, 아직 구현하지 않은
정산·실제 공급자 품질 평가·운영 배포 항목은 계속 후속 범위다.

## 1. 목표

이 계획의 목표는 경제 기능 한두 개가 아니라 이코빌리지 MVP에서 사용하는 AI 기능을
`ai-service`만으로 모두 생성·검증할 수 있게 만드는 것입니다.

MVP AI 기능군은 다음 여섯 가지입니다.

1. 경제 설정 추천·첫 경제활동 전 점검의 설명
2. 자동 모니터링 결과·경제 밸런싱 설명과 조정 제안
3. 교사용 AI 챗봇
4. AI 경제 이벤트 초안
5. 가상 투자 가격 단계에 연결된 AI 뉴스
6. 교사용 AI 퀴즈 초안

독립 MVP에서는 Spring이나 DB가 없어도 고정 fixture와 로컬 실행기로 각 기능의 요청부터
구조화 결과, 안전 검사와 평가까지 재현합니다. 이후 통합 단계에서는 fixture 입력만 Spring이
계산한 실제 입력으로 교체합니다.

## 2. 문서 우선순위와 책임 경계

구현 판단은 다음 순서로 따릅니다.

1. [AI 활용 방향](../AI_DIRECTION.md)의 확정 제품 범위와 책임
2. [내부 AI API 계약](INTERNAL_API_CONTRACT.md),
   [지표·임계값](METRICS_AND_THRESHOLDS.md),
   [안전·평가 기준](SAFETY_AND_EVALUATION.md)
3. 요구사항·RTM·API·상태·권한·화면·데이터·투자·퀴즈 공통 문서
4. [기계 판독 내부 OpenAPI](../../contracts/ai-internal-openapi.yaml)
5. 현재 `ai-service` 코드

문서와 코드가 다르면 상위 문서를 기준으로 계약과 코드를 고칩니다.

| 책임 | 운영 통합 시 담당 | AI 독립 MVP에서의 대체 수단 |
| --- | --- | --- |
| 선택한 모듈의 급여·세율·금리·가격·보상 후보와 추천·허용 범위 계산 | Spring 규칙 엔진 | 계산이 끝난 고정 fixture |
| 시작 전 `BLOCK·WARN` 판정 | Spring 규칙 엔진 | 판정 결과 fixture |
| 16개 경제 지표·임계값·구간 심각도 계산 | Spring 규칙 엔진 | 충분·부족·NORMAL·OBSERVE·WARN fixture |
| 7일 자동 실행·알림 중복 억제 | Spring 스케줄러·저장소 | 로컬 시나리오 실행기가 트리거를 재현 |
| 이벤트 효과와 투자 가격 경로 계산 | 규칙 엔진·투자 시뮬레이터 | 효과 요약·고정 가격 단계 fixture |
| 설명·요약·원인·대응안·이야기·뉴스·퀴즈 생성 | FastAPI AI 서비스 | 실제 구현 대상 |
| 구조·근거·범위·콘텐츠 안전 검사 | FastAPI와 Spring 이중 검증 | FastAPI 검증을 실제 구현 |
| 승인·저장·공개·정책 적용 | 교사·Spring·DB | `REVIEW_REQUIRED` 결과까지만 확인 |

AI 독립 MVP는 운영 규칙 엔진을 Python으로 다시 만드는 작업이 아닙니다. AI가 소유한 생성과
검증을 완성하고, 운영에서 받을 입력을 fixture로 재현하는 작업입니다.

## 3. 전체 기능 현황과 빠진 부분

현재 FastAPI에는 네 생성 경로, Pydantic 모델, 서비스 토큰·scope, 실행 문맥 검사,
deadline, 표준 오류, 결정적 fake provider와 실제 공급자 어댑터가 있습니다. 교사용 챗봇은
기능 전용 프롬프트·근거 연결·사전 제한 가드와 60개 평가 사례까지 완료했습니다. 교사용
퀴즈 초안 48개, 경제 설정 추천·시작 전 점검 48개, 밸런싱 60개, 경제 이벤트 42개,
투자 뉴스 32개와 공통 평가 60개를 포함해 독립 AI MVP 평가 기준선을 완성했습니다.

| 기능 | AI 입력 | AI 출력 | 현재 상태 | 독립 MVP에 필요한 보완 |
| --- | --- | --- | --- | --- |
| 설정 추천 설명 | Spring 후보값·범위·근거 코드, 학년·코스·모듈 | 후보별 이유·주의점 | 독립 MVP 완료 | 실제 규칙 엔진 후보 연결 후 문장 품질 opt-in 평가 |
| 시작 전 점검 설명 | 현재 설정, `BLOCK·WARN` 검사 결과 | 교사용 문제 설명·수정 안내 | 독립 MVP 완료 | 실제 사전 점검 결과 연결과 교사 화면 통합 |
| 자동 모니터링·밸런싱 | 분석 구간, 16개 지표, 심각도, 허용 action | 요약·근거·원인·범위 내 제안·효과·부작용 | 독립 MVP 완료 | 실제 규칙 엔진 지표·허용 action 연결과 7일 스케줄 통합 |
| 교사용 챗봇 | 학급 집계 사실·정책 이력·기간·질문 | 근거가 연결된 답변·원인·대응안·부작용 | 독립 MVP 완료 | 실제 공급자 자격증명 연결 후 문장 품질 opt-in 평가 |
| 경제 이벤트 | 7종 템플릿, 학년, 규칙 효과, 출처 | `REVIEW_REQUIRED` 이야기·선택지·진행 문구 | 독립 MVP 완료 | 실제 규칙 엔진 효과·교사 승인 화면 연결 |
| 투자 뉴스 | 시나리오 버전·가상 자산·목표 가격 단계까지의 사실 | 단계에 묶인 제목·뉴스·교사용 설명 | 독립 MVP 완료 | Spring 단계별 사전 생성·승인·공개 연결과 실제 공급자 문장 평가 |
| 퀴즈 초안 | 학년·난이도·개념·학습목표·분류·유형·개수 | 문제·선택지·단일 정답·해설·난이도·개념 태그 | 독립 MVP 완료 | 실제 공급자 자격증명 연결 후 문장 품질 opt-in 평가 |

여섯 기능군의 독립 생성·검증은 완료했습니다. 남은 일은 실제 공급자 자격증명으로 문장
품질을 평가하고, Spring 규칙 엔진·DB·스케줄러·교사 화면과 연결하는 통합 작업입니다.

## 4. AI 독립 MVP 완료 모습

AI 독립 MVP가 끝나면 다음을 할 수 있어야 합니다.

- 네 내부 생성 API에서 여섯 기능군의 확정 구조화 결과를 받습니다. 설정·운영 분석은
  `balancing`, 투자 뉴스는 `economic-event` 경로의 명시적 모드로 처리합니다.
- `FAKE` 공급자로 모든 fixture를 외부 호출 없이 빠르게 회귀 검증합니다.
- AWS Bedrock을 기본 실제 공급자로 호출하고, 관리자가 허용한 경우 OpenAI 어댑터로 같은
  요청·응답 계약을 사용합니다.
- 기능·학년·버전별 프롬프트를 코드와 분리해 선택하고 결과에 사용한 버전을 남깁니다.
- 로컬 실행기 한 번으로 여섯 기능군의 대표 시나리오와 실패 시나리오를 실행하고 결과를
  사람이 검토할 수 있습니다.
- [안전·평가 기준](SAFETY_AND_EVALUATION.md)의 최소 350개 평가 케이스와 출시 게이트를
  모델·프롬프트 조합별로 확인합니다.
- 개인 식별정보, 학생 개인 분석, 실제 금융조언, 범위 밖 수치, 승인 우회, 미래 투자정보가
  출력되면 성공 응답으로 반환하지 않습니다.

## 5. 단계별 구현 순서

각 단계는 계약·구현·자동 테스트·평가 fixture·문서를 함께 끝낸 뒤 다음 단계로 넘어갑니다.
Spring DTO, DB 마이그레이션, 외부 OpenAPI, 교사 화면은 이 계획이 완료된 뒤 별도 통합
계획에서 다룹니다.

### 1단계. 내부 AI 계약 v1.1과 기능 fixture 고정 — 완료 (2026-07-30)

목표: 모든 AI 기능이 필요로 하는 입력과 출력을 코드보다 먼저 고정합니다.

- `balancing` 요청을 `SETUP_PRECHECK·ON_DEMAND·AUTO_MONITOR`로 구분합니다.
- `SETUP_PRECHECK`에 `CLASSROOM_SETUP·PRODUCT_DRAFT·QUIZ_SESSION_DRAFT` 문맥과
  규칙 엔진 후보값·허용 범위·근거 코드·점검 결과를 추가합니다.
- 운영 분석에 트리거, 현재·이전 비중첩 구간, 심각도와 지표·임계값 버전을 명시합니다.
- 이벤트에 `TEACHER_REQUEST·MONITOR_RECOMMENDATION` 출처를 추가합니다.
- 투자 뉴스에 시나리오 버전, 자산, 가격 단계와 현재 단계까지 공개 가능한 사실을 추가합니다.
- 퀴즈 입력·출력에 난이도와 개념·개념 태그를 추가합니다.
- 내부 OpenAPI, Pydantic, API 계약 테스트와 성공·실패 JSON fixture를 함께 맞춥니다.

완료 기준:

- 확정 문서의 여섯 기능군이 내부 OpenAPI와 Pydantic에서 빠짐없이 표현됩니다.
- 알 수 없는 필드, 잘못된 모드·문맥·출처·학년·가격 단계·퀴즈 조합을 거절합니다.
- 아직 실제 모델 호출이나 Spring 코드는 변경하지 않습니다.

추천 커밋: `feat: 전체 AI MVP 내부 계약 v1.1 확장`

### 2단계. 공통 생성 런타임·프롬프트·검증 기반 — 완료 (2026-07-30)

목표: 기능마다 공급자 호출과 안전 처리를 중복 구현하지 않는 공통 기반을 만듭니다.

- 기능·모드·학년별 프롬프트 레지스트리와 버전 디렉터리를 추가합니다.
- 시스템 지침, 신뢰 입력, JSON 출력 스키마를 분리하고 요청에 임의 지침이 섞이지 않게 합니다.
- 공급자 독립 생성 인터페이스, 구조화 출력 파서와 오류 매핑을 구현합니다.
- schema → 문맥 → 근거 → 허용 범위 → 학년·효과 → 개인정보·금융조언 → 승인 경계 순으로
  공통 검증 파이프라인을 구현합니다.
- 실행 ID, 공급자, 모델, 프롬프트, 토큰, 지연시간, 검증 코드만 구조화 로그로 남기고 원문은
  기본 로그에서 제외합니다.
- fake provider를 새 계약 전체에 맞추고 의도적으로 잘못된 출력을 만드는 테스트 공급자를
  보강합니다.

완료 기준:

- 모든 기능이 같은 deadline·오류·검증·사용량 envelope를 사용합니다.
- 공급자 출력에 필드 추가·근거 조작·범위 이탈·개인정보·승인 우회가 있으면 차단됩니다.
- fake provider 회귀 테스트는 네트워크 없이 재현됩니다.

추천 커밋: `feat: AI 프롬프트 및 공통 생성 검증 런타임 구축`

### 3단계. Bedrock·OpenAI 실제 공급자 어댑터 — 완료 (2026-07-30)

목표: fake 계약 골격을 실제 구조화 생성으로 교체할 수 있게 합니다.

- AWS Bedrock 기본 어댑터와 관리자 허용 시 사용하는 OpenAI 어댑터를 구현합니다.
- 공급자별 구조화 출력 방식, timeout, 429·일시 장애와 토큰 사용량을 공통 오류로 변환합니다.
- 기능별 공급자·모델 라우팅과 환경변수 검증을 추가합니다.
- 자격증명이나 원문을 노출하지 않는 opt-in 실제 공급자 smoke test를 추가합니다.
- 한 FastAPI 요청에서 숨은 재시도를 하지 않고 상위 호출자의 최대 1회 재시도 계약을 유지합니다.

완료 기준:

- 같은 fixture가 fake와 실제 공급자에서 동일 Pydantic 응답 계약을 통과합니다.
- 공급자 미설정·호출 제한·장애·timeout이 안전한 표준 오류로 끝납니다.
- 기본 공급자는 Bedrock이고 OpenAI는 명시적으로 허용한 경우에만 선택됩니다.

추천 커밋: `feat: Bedrock 및 OpenAI 생성 어댑터 구현`

### 4단계. 교사용 AI 챗봇 완성 — 완료 (2026-07-30)

목표: 허용된 학급 집계 사실만으로 근거가 연결된 운영 답변을 생성합니다.

- 학급 설정·활성 모듈·경제·상점·금융·퀴즈 집계와 정책 이력용 프롬프트를 구현합니다.
- 답변에 근거 ID, 조회 기간, 데이터 시각, 원인, 대응안과 부작용을 연결합니다.
- 입력에 없는 사실을 추측하거나 학생 개인 분석·실제 금융조언·미래 예측을 요구하면
  안전한 제한 설명을 반환합니다.
- 정상, 상충 사실, 부족한 사실, 프롬프트 주입, 개인정보와 금융조언 사례를 평가합니다.

완료 기준:

- 모든 사실 주장과 대응안이 입력 fact ID에 연결됩니다.

외부 AI 호출 없이 결정적으로 계산합니다. 규칙 엔진 경계값 테스트 25건과 전체 백엔드
156건이 통과했고 실패·오류는 0건입니다(환경 의존 테스트 21건은 기존 조건에 따라 skip).

1. 실제 운영 날짜와 지급 간격으로 급여 지급 횟수를 계산합니다.
2. 현재 역할 배정·급여를 반영한 `S_ref`, 1단위 금액 반올림, 추천·허용 범위를 구현합니다.
3. 보상을 포함한 전체 발행액 중 기존·신규 보상 합계 25% 경고·30% 차단을 구현합니다.
4. `CLASSROOM_SETUP`, `MODULE_ACTIVATION`, `PRODUCT_DRAFT`, `QUIZ_SESSION_DRAFT`별 후보와
   `PASS·WARN·BLOCK` 판정을 구현하고 경계값 단위 테스트를 작성합니다.

완료 기준은 규칙 엔진이 AI 호출 없이도 결정적인 후보·점검 결과를 반환하는 것입니다.

### 8.4 단계 3 — 선택형 모듈과 정책 트랜잭션 완성

**상태: 완료 (2026-07-31, `S15P11B201-254`, `S15P11B201-256`)**

방 생성은 선택 모듈 0개를 허용하고 선택된 모듈도 초기에는 `DISABLED`로만 저장합니다.
역할·급여 모듈이 비활성 상태이면 학생 역할을 `null`로 저장하며 역할·정책·급여명세서
생성을 차단합니다. 모듈 활성화 명령은 선행 모듈, 상태 버전, 초기 정책, 규칙 엔진 판정을
검증한 뒤 정책 버전과 `ACTIVE` 전이를 같은 트랜잭션에서 저장합니다. 같은 멱등키는 기존
결과를 재생하고, 변경된 요청에 재사용할 수 없습니다. 모듈·학생·급여 정책 변경은 기존
`SETUP_PRECHECK` 결과를 만료시키며, 기존 금액 서비스의 지갑·원장 지연 생성 경계를
방 생성 회귀 테스트로 고정했습니다. 신규 통합·단위 시나리오 10건을 포함해 전체 백엔드
166건을 수집했고 실패·오류는 0건입니다(환경 의존 테스트 21건은 기존 조건에 따라 skip).

1. 방 생성 시 0개 이상의 선택 모듈을 `DISABLED`로 등록합니다.
2. 역할·급여 모듈이 없으면 학생 역할을 `null`로 유지하고 급여 역할·급여명세서를 만들지
   않습니다.
3. 금액 모듈이 처음 필요할 때 지갑·원장을 준비합니다.
4. 초기 정책 저장과 `DISABLED → ACTIVE` 전이를 한 트랜잭션으로 처리하고 실패 시 함께
   롤백합니다.
5. 설정·일정·학생·정책 변경 시 이전 시작 전 점검을 만료시킵니다.

완료 기준은 모듈 없음, 역할 없음, 조건부 선행 모듈, 재활성화와 롤백 시나리오의 통합
테스트가 통과하는 것입니다.
