## 2. 전체 디자인 방향

이코빌리지는 초등 경제교육 웹앱이므로 학생 화면은 학습 공간처럼 쉽고 밝게, 교사 화면은 반복 운영이 편한 관리 콘솔처럼 차분하게 만든다.

| 영역 | 톤 | 핵심 원칙 |
| --- | --- | --- |
| 학생 앱 | 파스텔 마을, 하늘색·민트, 도트 캐릭터 친화 | 짧은 문장, 큰 터치 영역, 본인 정보 중심 |
| 교사용 앱 | 수업 중 빠른 제어 도구 | 승인·시작·종료 같은 즉시 행동을 크게 배치 |
| 교사 관리 웹 | SaaS형 운영 콘솔 | 표, 필터, 요약 패널, 위험 알림을 우선 |
| 교실 공용 화면 | 교실 TV/빔 공유 화면 | 큰 글자, 익명 집계, 개인정보 비노출 |

학생 화면에서 캐릭터는 별도 도트 에셋을 얹는다. UI는 캐릭터를 새로 그리지 않고, 도트 PNG가 자연스럽게 들어가는 슬롯과 여백을 제공한다.

## 3. 공통 화면 규칙

### 3.1 상태 기반 노출

| 상태 | 화면 처리 |
| --- | --- |
| `AUTONOMOUS` | 학생은 활성 모듈만 자유 진입 가능 |
| `GUIDED` | 학생은 현재 지도 활동 화면으로 전환, 자유 활동은 잠금 |
| `CLOSED` | 조회 중심. 구매, 거래, 가입 같은 변경 버튼 비활성화 |
| `READ_ONLY` | 최종 리포트와 본인 기록만 조회 |
| 모듈 `DISABLED` | 학생 메뉴, 딥링크, 검색 결과에서 숨김 |

버튼은 단순히 숨기거나 비활성화하는 데서 끝내지 않고, 학생에게는 짧은 이유를, 교사에게는 해결 행동을 함께 보여준다.

### 3.2 개인정보와 공개 범위

- 공용 화면에는 학생 실명, 개인 잔액, 세금, 신용, 평가 원본, 개인 거래 내역을 노출하지 않는다.
- GAME 순위는 교사가 공개를 선택한 경우에만 닉네임과 장착 캐릭터 1~3위까지 표시한다.
- TEST 결과와 순위는 공용 화면에 표시하지 않는다.
- 교사 화면은 운영 목적상 학생 식별 정보를 표시할 수 있지만, 공용 화면 미리보기에는 공개 스키마만 보여준다.
- AI 관련 화면은 학생에게 노출하지 않고, 요청 데이터는 가명화·집계·최소 입력 기준을 따른다.

### 3.3 액션과 피드백

- 돈이 이동하는 행동은 실행 전 확인 모달을 둔다.
- 구매, 거래, 예금, 투자, 대출, 급여 지급은 낙관적 성공 처리 없이 서버 커밋 결과를 기다린다.
- 실패 메시지는 원인과 다음 행동을 분리한다. 예: 잔액 부족, 재고 없음, 마감됨, 최신 상태 변경.
- 중복 제출 방지를 위해 `처리 중` 상태에서는 버튼을 잠근다.
- 결과 화면에는 요청번호 또는 거래번호를 표시해 교사 문의와 감사 추적이 가능하게 한다.

## 5. 학생 앱 IA와 흐름

학생 앱은 `마을 광장`을 중심으로 움직인다. 교사가 허용한 모듈만 마을 카드로 보이며, 현재 수업 중이면 지도 활동 화면으로 전환된다.

```text
SCR-STU-001 로그인
  -> SCR-STU-003 경제교실 홈
    -> SCR-STU-004 지갑
    -> SCR-STU-005 월급명세서
    -> SCR-STU-006~007 상점·구매
    -> SCR-STU-008 캐릭터·보유 아이템
    -> SCR-STU-009~011 개인거래
    -> SCR-STU-012 공동기금·투표
    -> SCR-STU-013~020 금융
    -> SCR-STU-021~023 퀴즈·결과
    -> SCR-STU-024 최종 리포트
```

### 5.1 학생 홈 카드

| 카드 | 연결 | 노출 조건 | 기본 문구 |
| --- | --- | --- | --- |
| 이코 상점 | `SCR-STU-006` | 상점 ACTIVE | 상품을 사요 |
| 이코 은행 | `SCR-STU-013` | 금융 모듈 1개 이상 | 예금 가입 가능 |
| 투자 광장 | `SCR-STU-016` | 투자 모듈 ACTIVE | 투자 가능 |
| 월급명세서 | `SCR-STU-005` | 급여 사용 코스 | 내 급여 확인 |
| 마을 회의 | `SCR-STU-012` | 공동기금 또는 투표 LIVE | 공동기금 투표 |
| 이코 신용센터 | `SCR-STU-019~020` | 대출 모듈 ACTIVE | 대출·신용점수 |
| 캐릭터 | `SCR-STU-008` | 캐릭터/아이템 모듈 ACTIVE | 내 캐릭터 꾸미기 |

### 5.2 학생 화면 생성 우선순위

1. `SCR-STU-003` 마을 광장
2. `SCR-STU-005` 월급명세서
3. `SCR-STU-004` 지갑·거래 내역
4. `SCR-STU-006~008` 상점·구매·캐릭터
5. `SCR-STU-021~023` 지도 활동·퀴즈·결과
6. `SCR-STU-012` 공동기금·투표
7. `SCR-STU-009~011` 개인거래
8. `SCR-STU-013~020` 금융 확장
9. `SCR-STU-001~002`, `SCR-STU-024`

자세한 학생 화면 구상은 `docs/ui/STUDENT_PAGE_CONCEPT.md`, 디자인 페이지 구조는 `docs/design/STUDENT_DESIGN_PAGE.md`를 따른다.

## 6. 교사 IA와 흐름

교사 화면은 수업 중 빠른 제어와 관리 웹의 상세 설정을 분리한다.

| 업무 | 교사용 앱 | 교사 관리 웹 |
| --- | --- | --- |
| 로그인·담당 학급 선택 | 주 화면 | 주 화면 |
| 학생 앱 열기·닫기 | 주 화면 | 보조 |
| 지도 활동 시작·종료 | 주 화면 | 콘텐츠 준비 |
| 승인함 | 주 화면 | 상세 감사·검색 |
| 급여·활동 보상 | 빠른 지급 | 정책 설정·일괄 지급 |
| 교실 개설·정책·학생 명단 | 조회·알림 | 주 화면 |
| 분석·리포트·내보내기 | 요약 | 주 화면 |

### 6.1 교사 관리 웹 내비게이션

```text
대시보드
운영 센터
학생 관리
경제 관리
상점 관리
금융 관리
퀴즈·활동
리포트
설정
```

교사 관리 웹은 `상단 상태 바 + 좌측 메뉴 + 중앙 작업 영역 + 우측 요약 패널`을 기본 구조로 삼는다. 표와 필터를 적극 사용하고, 돈 이동·승인·정책 변경 화면에는 우측 요약 패널을 고정한다.

### 6.2 교사 핵심 흐름

```text
교사 로그인
  -> 경제교실 선택
  -> 경제교실 개설
  -> 학생 명단·역할급여 등록
  -> 모듈·정책 설정
  -> 대시보드
  -> 활동 시작·공용 화면 연결
  -> 승인·정산·리포트 확인
```

자세한 교사 화면 24종 설계는 `docs/ui/TEACHER_SCREENS_178_185.md`를 따른다.

## 7. 교실 공용 화면

공용 화면은 교실 TV나 빔에 띄우는 화면이다. 학생 화면과 같은 파스텔 톤을 쓰되, 읽는 거리가 멀기 때문에 글자와 숫자를 크게 만든다.

| 화면 ID | 화면 | 표시 정보 | 금지 정보 |
| --- | --- | --- | --- |
| `SCR-PUB-001` | 연결 대기 | 연결 코드, 활동 대기 상태 | 학생 목록, 잔액 |
| `SCR-PUB-002` | 퀴즈 진행 | 문제, 선택지, 타이머, 익명 응답 집계 | 개인 답안, 평가 원본, 잔액 |
| `SCR-PUB-003` | 투표·이벤트 진행 | 선택지, 이벤트 설명, 익명 집계 | 개인 선택, 금융정보 |
| `SCR-PUB-004` | 결과·순위 | 공개 결과, 교사 선택 시 1~3위 닉네임·장착 캐릭터 | 실명, 잔액, 세금, 신용, TEST 순위 |

### 7.1 공용 화면 레이아웃

- 기본 해상도는 1280x800, 빔 환경을 고려해 주요 텍스트는 32px 이상으로 둔다.
- 상단에는 `이코빌리지`, 활동명, 남은 시간만 배치한다.
- 중앙에는 현재 문제·선택지·집계 그래프를 크게 둔다.
- 하단에는 진행 단계나 안내 문구를 짧게 둔다.
- 배경은 학생 앱과 같은 하늘색·민트 톤을 쓰되, 장식 요소는 적게 둔다.

## 9. 생성기에 넘길 화면 입력

화면 생성 또는 API 설계는 아래 컨텍스트를 함께 넘긴다.

| 컨텍스트 | 설명 |
| --- | --- |
| `screen_id` | `SCR-STU-*`, `SCR-TCH-*`, `SCR-WEB-*`, `SCR-PUB-*` |
| `role` | `STU`, `OWN`, `COT`, `SAD`, `OPS`, `PUBLIC_DISPLAY` |
| `classroom_status` | 경제교실 상태 |
| `app_mode` | `AUTONOMOUS`, `GUIDED`, `CLOSED`, `READ_ONLY` |
| `module_status` | 모듈 선택 여부와 활성 상태 |
| `resource_status` | 주문, 거래, 예금, 투자, 퀴즈 등 개별 리소스 상태 |
| `privacy_scope` | 본인 전용, 교사 전용, 공용 공개 가능 여부 |
| `available_actions` | 현재 화면에서 실제 실행 가능한 행동 |
| `blocked_reason` | 버튼 숨김·비활성화 이유 |

## 10. 완료 체크리스트

- 모든 FE 화면은 `SCREEN_SPEC.md`의 화면 ID와 연결된다.
- 학생 화면은 마을형 IA와 도트 캐릭터 슬롯을 유지한다.
- 교사 화면은 반복 운영을 위한 콘솔 밀도를 유지한다.
- 공용 화면은 공개 스키마만 사용한다.
- 돈이 이동하는 행동은 확인, 처리 중, 성공, 실패 상태를 가진다.
- 모듈 미선택·비활성 상태는 학생에게 숨김, 교사에게 활성화 안내로 분리한다.
