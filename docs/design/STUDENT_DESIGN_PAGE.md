# 학생 앱 디자인 페이지

- 연결 구상: `docs/ui/STUDENT_PAGE_CONCEPT.md`
- 화면 기준: `docs/SCREEN_SPEC.md`의 `SCR-STU-001` ~ `SCR-STU-024`
- Jira 기준: `S15P11B201-190` ~ `S15P11B201-196`
- 목적: 학생용 화면을 한 번에 생성할 수 있도록 디자인 페이지 구조와 컴포넌트 기준을 정한다.

## 1. 디자인 페이지 구성

화면 생성 기준은 아래 페이지 또는 섹션 순서로 정리한다.

| 페이지 | 내용 |
| --- | --- |
| `00 Student Style` | 색상, 타이포, 공통 바, 버튼, 카드, 상태 배지 |
| `01 Student Home` | 로그인, 비밀번호 재설정, 마을 광장, 지도 활동 전환 |
| `02 Wallet Paystub` | 지갑, 월급명세서, 거래 상세 |
| `03 Shop Character` | 상점, 상품 상세, 구매 결과, 캐릭터, 보유 아이템 |
| `04 Trade Fund` | 개인거래, 공동기금, 익명 투표 |
| `05 Finance` | 금융 홈, 예금, 적금, 투자, 대출, 신용 |
| `06 Quiz Report` | GAME 퀴즈, TEST 응시, 결과, 최종 리포트 |
| `99 Assets` | 도트 캐릭터 에셋, 배경 이미지, 아이콘 후보 |

## 2. 아트보드 규칙

| 항목 | 값 |
| --- | --- |
| 기본 프레임 | `1280 x 800` |
| 여백 | 좌우 32~46, 상하 24~36 |
| 상단 개발 메뉴 | 높이 52 |
| 앱 헤더 | 높이 72~80 |
| 카드 그리드 | 3열 기준, 카드 간격 22~26 |
| 상세 화면 | 2열 또는 1+우측 요약 패널 |

프레임 이름은 `SCR-STU-003 / 마을 광장 / AUTONOMOUS`처럼 `화면 ID / 화면명 / 상태` 순서로 둔다.

## 4. 공통 컴포넌트

### 4.1 Top Dev Menu

상단의 어두운 메뉴다. 디자인 검토용 프로토타입에서는 화면 그룹 이동용으로 사용한다.

- 높이 52
- 배경 `nav-900`
- 활성 탭: `orange-500`
- 탭 예: `마을`, `자리`, `보험`, `신용`

### 4.2 App Header

학생이 실제로 보는 앱 헤더다.

```text
🏘️ 이코빌리지 | 현재 위치 pill | 1일차 | 💰 135비빔 | 학생
```

- 현재 위치 pill은 중앙 정렬
- 잔액 pill은 오른쪽에 고정
- 학생 실명은 표시하지 않고 닉네임 또는 `학생`만 표시

### 4.3 Village Card

홈의 핵심 카드다.

- 3열 배치
- 큰 아이콘 또는 건물 이미지 1개
- 카드명, 짧은 설명, CTA pill
- 상태 배지: `NEW`, `공사중`, `결과 공개`, `수업 후 열려요`

카드 예:

| 카드 | 아이콘 | 컬러 |
| --- | --- | --- |
| 이코 상점 | 상점 | orange |
| 이코 은행 | 은행 | purple |
| 투자 광장 | 차트 | red |
| 월급명세서 | 가방 | green |
| 마을 회의 | 체크/회의 | muted |
| 이코 신용센터 | 카드 | sky |

### 4.4 Receipt Card

월급명세서와 구매 상세에 쓰는 영수증형 카드다.

- 상단 띠: `orange-500`
- 본문 행: 받은 돈, 세금, 총액
- 최종 금액 박스: 초록 테두리와 큰 금액
- 세금 행은 빨간/살구 배경으로 분리

### 4.5 Result Summary

투자 결과, 퀴즈 결과, 최종 리포트에 쓰는 요약 카드다.

- 왼쪽: 결과 리스트
- 오른쪽: 최종 정산 내역
- 성공/이익은 초록, 손실/차감은 빨강
- 공용 화면에 표시되는 정보와 본인에게만 보이는 정보를 분리한다.

### 4.6 Character Slot

캐릭터는 64×64 논리 캔버스를 사용한다. 상세 규칙은
[도트 캐릭터 이미지 작업 규격](CHARACTER_ASSET_SPEC.md)을 따른다.

- 슬롯 배경은 흰색 또는 매우 연한 하늘색
- `image-rendering: pixelated` 적용, 표시 크기는 `64px × 정수 배율`만 사용
- 컨테이너 폭에 맞춘 `%` 크기나 비정수 배율은 사용하지 않는다 (도트가 흐려진다)
- 장착 아이템 슬롯은 `AVAILABLE`, `EQUIPPED`, `LOCKED_TRADE` 상태를 가진다.
- 캐릭터 에셋은 `assets/character/`를 기준으로 한다.

## 5. 화면별 디자인 구상

### 5.1 `SCR-STU-003` 마을 광장

- 홈 화면은 `FE_SCREEN_GENERATION_SPEC.md`의 `SCR-STU-003` 규칙을 따른다.
- 3열 기능 카드, 상단 상태 헤더, 파스텔 마을 배경, 모듈별 컬러 border를 사용한다.
- 3열 기능 카드
- 상단에는 구름/나무/마을 장식 가능
- 비활성 카드는 흐리게 처리하고 `공사중` 배지 표시
- 선택하지 않은 모듈은 아예 숨김

### 5.2 `SCR-STU-005` 월급명세서

- 월급명세서는 `FE_SCREEN_GENERATION_SPEC.md`의 `SCR-STU-005` 규칙을 따른다.
- 왼쪽 Receipt Card와 오른쪽 세금 설명·돈 흐름 패널을 2열로 구성한다.
- 왼쪽 큰 급여 명세서, 오른쪽 세금 설명과 돈 흐름
- 최종 입금액은 가장 큰 글자로 표시
- 학생이 눌러야 하는 버튼은 `확인했어요!` 하나로 단순화

### 5.3 `SCR-STU-021` 선생님 수업

- 선생님 수업 화면은 `FE_SCREEN_GENERATION_SPEC.md`의 `SCR-STU-021`, `SCR-STU-022` 규칙을 따른다.
- 왼쪽 학습 목차, 중앙 학습 카드, 오른쪽 잠금 리스트 구조를 유지한다.
- 왼쪽 오늘의 학습 목차
- 중앙 큰 학습 카드
- 오른쪽 마을 기능 잠금 리스트
- `GUIDED` 상태에서는 자유 활동 CTA를 숨김 또는 비활성화

### 5.4 `SCR-STU-018` 투자 결과

- 투자 결과 화면은 `FE_SCREEN_GENERATION_SPEC.md`의 `SCR-STU-018` 규칙을 따른다.
- 상단 결과 헤더, 종목별 결과 리스트, 오른쪽 최종 정산 패널을 사용한다.
- 상단에 어두운 결과 헤더와 `마을로` 버튼
- 종목별 결과 카드는 세로 리스트
- 오른쪽 최종 정산 내역과 안내 카드
- 금융소득세는 별도 차감 행으로 표시

### 5.5 `SCR-STU-008` 캐릭터·보유 아이템

- 캐릭터 미리보기는 좌측 큰 영역
- 우측에 아이템 탭: 추천, 모자, 얼굴, 상의, 하의, 신발, 배경
- 코드 기반 도트 캐릭터가 주인공이므로 UI 장식은 얇게 유지
- 아이템 카드에는 가격, 보유/착용/부족 상태를 표시

## 6. 상태별 변형

| 상태 | 디자인 변형 |
| --- | --- |
| 기본 | 활성 CTA, 선명한 카드 |
| 잠김 | 카드 투명도 50%, CTA 제거, 잠금 사유 표시 |
| 처리 중 | CTA 로딩, 중복 탭 방지 문구 |
| 성공 | 초록 결과 카드, 다음 행동 1개 |
| 실패 | 빨간 안내 카드, 원인과 재시도 조건 |
| 읽기 전용 | CTA 숨김, 조회 가능 기간 표시 |

## 7. 생성 전 체크리스트

- 모든 화면에 `SCR-STU-*` ID를 프레임명에 포함
- Jira `S15P11B201-190~196` 단위로 섹션 구분
- 홈, 월급명세서, 선생님 수업, 투자 결과를 우선 고해상도 완성
- 캐릭터는 placeholder가 아니라 실제 코드 기반 도트 렌더러로 톤 검증
- 공용 화면에 노출 금지인 개인 잔액·세금·신용·평가 원본은 디자인에도 넣지 않음
- 버튼 문구는 행동 1개당 하나만 명확히 표시
- 긴 설명은 보조 카드로 빼고 메인 카드는 짧게 유지
