# 2026-07-29 캐릭터 꾸미기 소비 모듈 기획

- 상태: 후보 범위 (MVP 확정 아님, 고도화 검토)
- 목적: 학생이 교실 화폐 `비빔`으로 **캐릭터에 입힐 코스메틱(옷·아이템·배경)** 을 구매·착용하는 소비 활동을 추가한다.

## 1. 핵심 컨셉

- 학생은 **기본 캐릭터 1종('이코')** 을 무료로 받는다.
- `비빔`으로 코스메틱을 **구매(소비)** 하고, 산 아이템을 캐릭터에 **입힌다(착용)**.
- 다양성은 캐릭터 종류가 아니라 **구매한 상품 조합**에서 나온다. → 같은 캐릭터가 산 상품대로 다른 스타일로 보인다.
- 학습 목표: 반복 소비·예산·기회비용·욕구 관리.

## 2. 가장 중요한 설계 원칙 — 이것은 "소비" 모듈이다

- 돈은 **한 방향(지갑 → 소비 싱크 계정)으로만** 나가고 절대 돌아오지 않는다. (예금·투자와의 결정적 차이)
- 보상은 성장·꾸밈 등 **정서적 만족**이며, 비빔은 환급되지 않는다.

## 3. 기술 방향 (확정)

- **렌더링/클라이언트: PixiJS + React** (Unity 대신 채택 — 경량·웹 통합 용이)
  - Pixi `Application`(WebGL 캔버스)를 React 컴포넌트에 마운트
  - 페이퍼돌: base + 슬롯별 `Sprite` 레이어를 z-order로 겹침, 코스메틱은 `sprite.texture` 교체
  - 도트 선명도: 텍스처 `scaleMode: 'nearest'`
  - 에셋: 스프라이트 아틀라스(PNG+JSON, TexturePacker/free-tex-packer) → `Assets.load`
  - 인증: 기존 쿠키 세션 재사용(웹이므로 별도 토큰 불필요)
- **백엔드/DB: 기존 Spring Boot + PostgreSQL 원장 그대로.** Pixi/React는 REST로 통신만 한다.
- 프레임워크 메모: 현재 프론트는 Vue. 권장 = 학생 클라이언트만 React+Pixi, 교사·관리자는 Vue 유지. (Pixi는 Vue에도 붙일 수 있음)

## 4. 저작권(IP) 가이드 — 반드시 준수

- '곰돌이 푸' 원작은 **미국 기준** PD이며, **한국은 Shepard 삽화가 약 2046년까지 보호될 수 있어** 리스크가 있다.
- 따라서: 디즈니 디자인(빨간 셔츠 등)·브랜드명("Winnie the Pooh"/"티거"/"피글렛")을 **사용하지 않고**, "고전 곰/동물 아키타입"에서 **오리지널로 변형(transformative)** 한 도트만 사용한다.
- 학교 배포 전 법무/변리사 확인 권장.

## 5. 캐릭터 사양

- 기본 캐릭터: '이코' — **팔 없는(무팔) 부드러운 둥근 도트** 확정. 흰 몸통 + 회색 외곽선, 점 눈·볼터치·미소. 다양성은 코스메틱에서.
- 스타일: 흰 몸통 아웃라인 픽셀 톤. 눈·입은 솔리드 짙은 회색.
- 픽셀 규격: 셀 7px. **외곽선 = 흰 실루엣을 8방향으로 밀어 자동 생성**(연결부 도트 빠짐 방지). 몸통 윤곽 짙게 + 발 연하게 2톤.
- 체형 4단계 조합(확정): **통통=새 버전**(옆구리 축소 + 볼·턱 좌우 1px 미세 확장) / **기본·날씬·매우 날씬=이전 부드러운 egg 버전**(얼굴 변화 없음). 표정·얼굴 위치·전체 키·모자 앵커는 4개 공용 고정.
- 이름: 입양 시 학생이 직접 입력, 기본값 '이코', 부적절어 필터.
- **앵커 그리드 고정** → 나중에 기본 캐릭터 모양을 바꿔도 옷 에셋 재사용.

## 6. 코스메틱 슬롯 & 규칙 (결정 기록)

슬롯: `모자 / 얼굴 / 목 / 상의 / 신발 / 등 / 손 / 효과 / 배경` (슬롯당 1개 착용)

- 레이어 순서: `배경 → 효과 → 등 → base → 상의 → 신발 → 목 → 얼굴 → 손 → 모자`
- 상품은 `기본 / 계절 / 스포츠 / 직업 / 판타지 / 행사` 중 하나의 주 테마를 가진다.
- 체형별 에셋은 별도 상품이 아니며 한 번 구매하면 모든 체형에서 자동 적용된다.

| # | 항목 | 확정 |
| --- | --- | --- |
| D1 | 소비 싱크 계정 | 전용 `CHARACTER_EXPENSE` 신설 (CLASS_EXPENSE는 공동비용 전용) |
| D2 | 입양 시점 | 지연 생성 — 캐릭터 화면 첫 진입 시 무료 생성 |

## 7. 데이터 모델 (Flyway V30~)

```sql
student_characters              -- 학생당 1개, 무료 생성
  id, room_id, student_id, name(기본 '이코'),
  equipped JSONB{slot: cosmeticId}, created_at
  UNIQUE(room_id, student_id)

character_cosmetics             -- 코스메틱 카탈로그 (방 스코프, 고정 시드)
  id, room_id, name,
  slot(HAT/FACE/NECK/TOP/SHOES/BACK/HAND/EFFECT/BACKGROUND),
  theme(BASIC/SEASONAL/SPORTS/CAREER/FANTASY/EVENT),
  price, sprite_key, anchor JSONB, display_order, status

character_cosmetic_ownership    -- 소유 = 소비 이력(원장 연결)
  id, character_id, cosmetic_id, transaction_id, price_paid, created_at
  UNIQUE(character_id, cosmetic_id)
```

- 구매 흐름: `ShopService.purchase()` 패턴 재사용 (Idempotency-Key → wallet row lock → 소유 검사 →
  잔액 검증 → financial_transaction(COSMETIC_PURCHASE) → 이중부기(지갑 -price, CHARACTER_EXPENSE +price)
  → ownership insert → room.markEconomicStateChanged()).
- equip: 돈 이동 없음, `equipped` JSONB만 PATCH.

## 10. 이스터에그 — 경제 상태 반영 체형 (옵션)

### 10.1 체형 4단계
- 내부 상태값 `CHUBBY / BASE / SLIM / VERY_SLIM` (통통·기본·날씬·매우 날씬). "매우 통통"은 제외.
- 매핑: 저축(잔액) 많음 → CHUBBY · 균형 → BASE · 소비 많음 → SLIM · 소비 최고 → VERY_SLIM.
- 지표: 절대금액이 아니라 **소득 대비 비율**(잔액/소득, 누적소비/소득). 히스테리시스로 경계 깜빡임 방지.
- 변화 간격: **CHUBBY↔BASE↔SLIM은 뚜렷, SLIM↔VERY_SLIM은 미세**하게.

### 10.2 몸·얼굴 변화 규칙 (핵심)
- **몸 100% : 얼굴 20~30%** — 얼굴은 몸보다 약하게 변한다. 얼굴 전체 크기를 바꾸면 머리·몸이 따로 노는 느낌.
- **고정(모든 체형 동일)**: 머리 꼭대기·관자놀이 폭, 눈·코·입 위치, 전체 키, 모자 앵커, 얼굴 중심 앵커.
- **변화(체형별)**: 볼·턱선, 목–몸 연결부, 몸통 폭.
  - CHUBBY: 옆구리 날개부터 축소(몸 폭 우선) + 볼·아래턱만 좌우 1px 확장(전체 확대 금지 — 더 뚱뚱해 보임).
  - BASE: 기준.
  - SLIM: 몸통 폭 소폭 축소 + 아래 볼만 좌우 1px 축소.
  - VERY_SLIM: 날씬보다 조금 더 축소 + **턱선만** 추가 축소.
- **표정 동일**: 어떤 체형도 더 행복/매력적으로 보이지 않게 눈·입·볼터치 동일.

### 10.3 에셋 처리 방식 (작업량 최소화)
- 머리 상단 고정 → **모자·안경은 1개 에셋 공용**. 자동 확대·축소 금지(도트 찌그러짐·선 두께 변화·흐림) → **동일 크기 + 체형별 위치 보정**(`hatTransform`, 머리 상단 고정이라 대부분 {0,0}).

| 상품 | 처리 |
| --- | --- |
| 모자·머리띠 | 공용 |
| 안경·얼굴 장식 | 눈 위치 고정 → 공용 |
| 목걸이·목도리 | 체형별 위치 보정 또는 별도 |
| 상의·하의·신발 | **체형별 에셋** |
| 가방·망토·날개 | 체형별 위치 보정, 필요 시 별도 |

- 머리를 감싸는 우주 헬멧·기사 투구·공룡 후드·면사포만 `BODY_VARIANT`로 체형별 제작한다. 일반 캡과 비니는 공용이다.
- 상의·하의·신발과 몸을 감싸는 목도리·튜브는 체형별 4버전 제작한다.
- 가방·날개·검·마법봉 등은 원본 1개에 체형별 정수 좌표만 보정한다. 상세 규칙은 asset-spec 문서를 단일 기준으로 사용한다.

### 10.4 화면 표기·안전 정책 (중요)
- **화면에 경제 상태 문구를 체형과 직접 연결하지 않는다.** 체형명(통통 등)도 **내부 상태값으로만** 사용, 학생 화면 미표기 → "소비할수록 더 좋은 체형" 인상 방지.
- 3~4단계로 **부드럽게**(극단 회피), **본인만 비공개**, **교사 토글**로 끌 수 있게.
- 주의: 초4~6·학교 제품 특성상 체형-돈 매핑은 낙인·바디이미지 리스크가 있어 두 차례 우려를 제기했으나 기획자 판단으로 채택. 담당팀 검토 후 활성화 권장. 안전 대안(소품형: 동전탑/쇼핑백)도 병기.

### 10.5 렌더링 메모
- 외곽선은 실루엣을 8방향으로 밀어 자동 생성(연결부 도트 빠짐 방지). 몸통 윤곽은 짙게, 발은 연하게 2톤.
