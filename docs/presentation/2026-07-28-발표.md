# 경제교실 지속형 MVP 진행상황 발표

- 발표일: 2026년 7월 28일
- 목표: 현재까지 확정한 제품 구조와 다음 개발 단계를 팀에 공유
- 현재 단계: MVP 정책·범위 확정 완료, 상세 도메인·ERD·API 설계 착수 전

---

## 1. 우리가 만들고 있는 것

> 교사가 운영기간, 규칙과 모듈을 설정하면 학생이 학교의 자율시간과 교사 지도 활동에서 지속적으로 경제활동을 경험하는 모듈형 경제교육 플랫폼

- 정규 교과의 고정 진도보다 점심시간, 쉬는시간, 자유시간 등 재량시간의 간헐적 사용을 우선합니다.
- 학생은 학교 지급 개인 태블릿으로 이용합니다.
- 교사가 허용한 시간에는 상점, 개인거래, 예금과 경제 학습을 학생이 자율적으로 이용합니다.
- 퀴즈, 테스트, 투표처럼 함께 진행해야 하는 활동은 교사가 시작하고 학생 화면과 공용 화면을 같은 활동으로 연결합니다.
- 한 번의 체험으로 끝나지 않고 소득, 소비, 저축, 거래와 선택 결과가 계속 누적됩니다.

## 2. 세 화면의 역할

| 화면 | 주요 역할 | 공개 범위 |
| --- | --- | --- |
| 교사 운영 웹 | 경제교실 개설, 정책·모듈 설정, 자율시간 관리, 활동 진행, 거래 승인, 리포트 확인 | 학생별 잔액·기록과 운영 정보 |
| 학생 태블릿 앱 | 지갑, 상점, 개인거래, 예금, 퀴즈·테스트·투표 참여, 개인 리포트 | 본인 정보와 허용된 학급 정보 |
| 교실 공용 화면 | 문제, 타이머, 익명 집계, 게임 결과와 활동 진행상태 표시 | 수업에 필요한 공개 정보만 |

핵심은 **같은 경제교실의 사건과 상태를 공유하되 화면과 권한을 역할별로 분리하는 것**입니다.

## 3. 전체 운영 흐름

1. **경제교실 개설**
   - 학년, 학생 수, 운영기간, 사용할 모듈, 역할별 월급, 세금·부가세와 학생 자율시간 설정
2. **학생 계정 연결**
   - 학급 입장 주소 또는 QR로 접속하고 출석번호·닉네임·비밀번호로 학교 태블릿 연결
3. **자율 이용**
   - 교사가 연 시간에 상점, 개인거래, 예금과 학습 활동 이용
4. **교사 지도 활동**
   - 게임 퀴즈, 테스트, 투표 등을 시작하면 학생 앱이 해당 학생용 활동 화면으로 이동
5. **거래와 학습 기록 누적**
   - 모든 금액 이동과 선택 결과를 원장과 활동 기록에 저장
6. **리포트**
   - 학생은 자신의 자산과 학습 결과를, 교사는 학급 운영 현황을 확인

## 4. 모듈형 구조

### 항상 포함되는 기반

- 교사·학생 계정과 경제교실
- 태블릿 연결과 비밀번호 인증
- 지갑과 거래 원장
- 자율 이용·지도 활동 제어
- 알림, 기본 리포트와 감사 기록

### 선택 가능한 MVP 모듈

- 월급명세서·소득세
- 게임 퀴즈
- 테스트 퀴즈
- AI 문제 생성
- 캐릭터·디지털 아이템
- 공식 디지털 상점
- 실제 상품 상점
- 개인 아이템 거래소
- 정기예금
- 부가세
- 학급 공공기금·예산·투표

### MVP 이후 확장 모듈

- 적금, 주식투자, 보험, 대출·신용
- 시장가격·물가
- 학생 운영 상점·재고·매출·이익
- 부동산·자리 이용권
- 주거·청약
- 복지·사회안전망 고급 정책

자리 이용권은 상점 상품이 아니라 부동산 모듈의 **기간형 교실 공간 이용권**으로 다룹니다.

### 모듈 운영 원칙

- 학년과 기간 템플릿에 따라 추천 모듈을 보여주지만 최종 선택은 교사가 합니다.
- 선택하지 않은 모듈은 학생 앱에서 숨깁니다.
- 운영 중 모듈을 추가할 수 있습니다.
- 모듈을 중지해도 기존 기록은 보존하고 신규 이용만 차단합니다.
- 필요한 기술 의존성이 빠졌다면 시스템이 자동 추가하고 이유를 안내합니다.
- 선수개념은 추천과 안내에 활용하지만 교사의 선택을 강제로 막지는 않습니다.

## 5. 추천 코스와 기간 템플릿

코스는 고정 교육과정이 아니라 경제교실을 빠르게 개설하기 위한 **초기 설정 템플릿**입니다. 교사는 학년과 수업 상황에 맞게 모듈·일정·콘텐츠를 수정할 수 있습니다.

### 공통 학습 사이클

`지갑·거래기록 → 활동·총소득 → 월급명세서·세금 → 실수령액 → 예산계획 → 소비 → 계획·실제 비교 → 저축·기간형 선택 → 리포트`

1회 체험에서는 기간형 상품을 생략하고 남은 돈의 배분과 선택 이유를 확인하며 마무리합니다.

### 기간별 구성

| 기간 | 핵심 구성 |
| --- | --- |
| 1회 | 지갑 → 소득 → 세금·명세서 → 소비 → 남은 돈과 기회비용 |
| 1주 | 첫 활동에서 지갑·명세서·세금·예산·상점·예금 선택 → 중간 자율활동 → 마지막 예금 결과·공공기금 투표·리포트 |
| 4주 | 공통 경제 흐름을 반복하면서 학년별 중점 개념을 단계적으로 추가 |
| 8주 | 1~2주 공통 기반 → 3~6주 학년별 트랙 → 7주 공공의사결정 → 8주 최종 자산·학습 리포트 |

### 4주 학년별 중점

| 학년 | 추천 흐름 |
| --- | --- |
| 초4 | 지갑·소득·소비 → 예산 → 저축목표·예금 → 공공기금·리포트 |
| 초5 | 월급명세서·세금 → 예금·기초 투자 → 가격 변화 → 공공기금·리포트 |
| 초6 | 세금 → 시장가격·물가 → 공공예산·복지 → 정책 투표·리포트 |
| 중1 | 예산·비상금 → 예금·위험 → 보험·대출 → 신용·리포트 |
| 중2 | 소비자·상점 → 생산·재고 → 가격결정 → 매출·원가·이익 |
| 중3 | 저축·투자 → 위험과 분산 → 대출·주거 → 청약·자산 리포트 |

MVP 이후 모듈이 필요한 주제는 해당 거래 기능이 준비되기 전까지 학습 콘텐츠나 교사 진행 활동으로만 제공합니다.

## 6. 핵심 경제 흐름

`소득·보상 → 지갑·거래 원장 → 상점 / 개인거래 / 예금 → 학급 공공기금 → 리포트`

- 월급과 활동 보상이 학생 지갑에 들어옵니다.
- 소득세와 공식 상점·개인거래의 부가세는 학급 공공기금으로 이동합니다.
- 상점, 개인거래와 예금은 같은 거래 원장 원칙을 따릅니다.
- 정책을 바꿔도 과거 거래에는 거래 당시 세율과 조건이 정책 스냅샷으로 남습니다.
- 완료된 거래는 수정하거나 삭제하지 않습니다.
- 운영 오류는 원거래를 참조하는 반대 방향의 **복구 거래**로 정정합니다.

## 7. 개인거래 흐름

1. A가 B를 선택하고 아이템과 고정가격을 입력해 거래를 제안합니다.
2. 제안 시점의 부가세와 거래 조건을 고정합니다.
3. B가 거래 내용에 동의합니다.
4. 거래가 학급 개인거래소의 승인 대기 내역에 올라갑니다.
5. 교사가 최종 승인하거나 거절합니다.
6. 승인 시 구매자 결제, 판매자 수령, 공공기금 세금 적립과 아이템 소유권 이전을 한 번에 처리합니다.

같은 아이템의 중복 거래를 막기 위해 진행 중에는 아이템을 잠급니다. 자율시간이 닫히면 제안은 보존하지만, 개인거래소 모듈 자체를 중지할 때는 미완료 제안을 취소하고 잠금을 해제합니다.

## 8. 퀴즈와 캐릭터

### 게임 퀴즈

- 경제 문제와 넌센스 문제를 빠르게 푸는 카훗형 활동
- 참여·정답·속도 보상을 분리하고 속도 보상에는 상한 적용
- 결과 화면에 1~3위의 닉네임과 캐릭터 표시

### 테스트 퀴즈

- 학습 확인과 평가 목적
- 자동 저장과 시간 종료 제출 지원
- 학생은 본인 결과만 확인하고 공개 순위는 제공하지 않음

### AI 문제 생성

- 학년, 주제, 난이도와 문제 유형을 입력해 초안을 생성
- 교사가 정답, 해설, 표현과 난이도를 검토·승인한 문제만 사용
- 학생 성적과 개인 경제 데이터는 생성 요청에 포함하지 않음

### 캐릭터

- 디지털 아이템 상점·인벤토리와 연결
- 권리가 확인된 퍼블릭 도메인 원전을 바탕으로 자체 제작하거나 정식 라이선스 에셋 사용
- 단순 꾸미기를 넘어 퀴즈 결과와 학생 식별에 활용

## 9. 현재까지 확정한 핵심 정책

- 학생 실명, 이메일과 전화번호를 수집하지 않고 출석번호·닉네임·비밀번호를 사용합니다.
- 비밀번호 입력 실패 횟수로 계정을 잠그지 않으며, 재설정 후에도 닉네임은 유지합니다.
- 정상 완료한 공식 상점 구매와 개인거래에는 학생 취소·환불 기능이 없습니다.
- 예금 가입과 중도해지는 신용점수에 직접 영향을 주지 않습니다.
- 대출·신용은 MVP 이후 별도의 교실용 시뮬레이션 모듈로 운영합니다.
- 게임 퀴즈 상위 3명 외에는 학생의 잔액, 세금, 테스트 결과와 신용을 다른 학생에게 공개하지 않습니다.
- 정책 결정 C-01~C-41과 문서 간 충돌 검토를 완료했습니다.

| 영역 | 기술 |
| --- | --- |
| 학생·교사 프론트엔드 | Vue 3, TypeScript, Vite |

| 백엔드 테스트 | JUnit |
| 로컬·배포 기반 | Docker, Docker Compose, Nginx |
| CI/CD 계획 | Jenkins |

### 목표 통신 구조

- 일반 조회와 명령: HTTP API
- 지도 활동, 타이머, 운영 모드와 공용 화면 상태: WebSocket
- WebSocket 연결 실패 시 제한적 주기 조회로 현재 상태 복구
- 지급·구매·제출 요청에는 중복 방지 식별자를 적용
- 금액 변경과 타이머 판정의 최종 기준은 서버

학생 클라이언트는 현재 Vue 기반 웹으로 구현되어 있으며, 학교 태블릿 배포 방식은 상세 설계 단계에서 확정합니다.

## 30초 요약

경제교실은 학생 태블릿 앱, 교사 운영 웹과 교실 공용 화면이 연결된 지속형 학급 경제 플랫폼입니다. 교사가 기간, 정책, 모듈과 자율시간을 설정하면 학생은 학교 안에서 상점, 개인거래, 예금과 경제 학습을 자율적으로 이용하고, 퀴즈·테스트·투표 같은 지도 활동에서는 세 화면이 실시간으로 연결됩니다. 코스는 1회·1주·4주·8주 추천 템플릿으로 제공하되 교사가 자유롭게 수정할 수 있습니다. 현재 MVP 범위와 핵심 정책 정리는 완료했으며, 다음 단계는 API 명세 전에 상세 도메인, ERD, 상태와 권한을 확정하는 것입니다.
