## 3. 의도적으로 유지한 차이

- 실제 상품 상점은 MVP 기능이지만 모든 코스에서 선택 모듈입니다.
- 교사는 학년 기본 추천에 없는 모듈을 추가할 수 있으며 해당 학년 난이도 프로필을 적용합니다.
- 학생·교사용 앱과 관리자·교사 관리 웹은 기능이 겹칠 수 있지만 같은 권한 정책과 API를 사용합니다.
- AI는 조정값을 제안할 수 있지만 교사 승인 없이 적용하지 않습니다.
- `1회`는 추천 규모 중 하나지만 경제 원장·금융상품을 만들지 않는 별도 경량 흐름입니다.
- 코스 모듈 추천과 AI 경제 이벤트의 학년별 콘텐츠 제한은 별도 기준입니다. 초5 1학기에는 교육용 대출을 추천하지만 AI 이벤트의 대출금리 소재는 초6에서만 사용합니다.

## 4. 남은 구현·검증 항목

다음은 제품 정책 충돌이 아니라 후속 구현·검증 작업입니다.

- Docker 사용 가능 Jenkins에서 Testcontainers 20개 전체 실행
- [API 필드 매핑](../../contracts/api-field-mapping.json) 기반 클라이언트·서버 인터페이스 생성
- 계약 기반 클라이언트·서버 인터페이스 생성
- 역할·상태·오류·outbox 재시도를 포함한 서비스·E2E 인수 테스트와 백로그 연결
- 실제 서비스 쿼리의 `EXPLAIN ANALYZE` 기반 인덱스 조정

논리 ERD는 [논리 데이터 모델](../DATA_MODEL.md), 테이블·자료형·인덱스·제약조건과 Flyway·DBT 구현은 [물리 스키마](../PHYSICAL_SCHEMA.md)에서 관리합니다.

핵심 상태 전이 기준은 [상태 머신](../STATE_MACHINES.md)에서 관리합니다.

역할·리소스·상태별 권한은 [역할·권한 매트릭스](../PERMISSION_MATRIX.md)에서 관리합니다.

역할·상태별 화면·행동과 공개 화면 경계는 [화면 ID·행동 명세](../SCREEN_SPEC.md)에서 관리합니다.

인증·응답·오류·멱등성·동시성·시간·금액 계약은 [API 공통 규칙](../API_COMMON_RULES.md)에서 관리합니다.

화면 행동별 HTTP 명령·조회·오류 연결은 [HTTP API 명세](../HTTP_API_SPEC.md)에서 관리합니다.

실시간 채널·이벤트·공개 projection·재연결은 [WebSocket 명세](../WEBSOCKET_SPEC.md)에서 관리합니다.

구현 도구가 읽는 HTTP·실시간 스키마는 [OpenAPI](../../contracts/openapi.yaml)와 [AsyncAPI](../../contracts/asyncapi.yaml)에서 관리합니다.
